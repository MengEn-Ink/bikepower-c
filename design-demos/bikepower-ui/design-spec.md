# BikePower 监控页与骑行端配置页 · 三方向共同 Spec

## 本质需求

让同一套 BikePower 主题在两个距离完全不同的场景中成立：

1. 桌面监控端：工程人员连接、判断设备是否健康、看实时骑行数据、再下钻协议/刷机/比对。
2. 手机配网页：骑行者在热点剩余时间内快速配置输出并安全退出 WiFi。

## 受众与场景

- 监控端：开发者、测试者和高级用户；约 1m 笔记本距离；信息密度高但异常优先。
- 配置端：设备所有者；10–30cm 手机距离；单手操作、时间有限、保存动作明确。

## 两页核心叙事

- 监控：连接状态 → 三路实时数据及走势 → 数据新鲜度/异常 → 设备与协议下钻。
- 配置：当前输出目标 → 来源与幅度 → 心率联动 → 广播字段 → 保存/关闭 WiFi → 次级设备设置。

## 输出与尺寸

- 每个方向一个完整、可交互、单文件 HTML。
- HTML 内可切换“监控台 / 骑行配置”。
- 桌面验收：1440×900；移动验收：390×844（同时验证 375px）。
- 方向阶段只做高保真前端原型，不改生产固件页面，不连接后端。

## 真实内容约束

- 保留现有功能名称与语义，不发明云端能力。
- 示例曲线和数值显式标为“演示状态”。
- 监控端必须显示 BLE 授权由用户触发。
- 配置端必须显示配网倒计时、ERG 接管和“保存并关闭 WiFi”的后果。

## 页面 Form 五问

### 监控页

- 叙事角色：实时证据页，不是入口菜单。
- 观众距离：1m 笔记本。
- 视觉温度：冷静、紧张度可读，但不是电竞风。
- 容量：首屏容纳状态、三指标、一张联合时间图、异常与设备摘要；协议详情下钻。
- 视觉母题：每 50ms 生成、每秒被看见的骑行信号；“时间轴上的三条证据”。

### 配置页

- 叙事角色：限时设置向导，不是系统设置仓库。
- 观众距离：10–30cm 手机。
- 视觉温度：确定、直接、可撤回。
- 容量：首屏先完成 80% 骑行配置，设备/LED/模板进入次级层。
- 视觉母题：目标瓦数是一条骑行基线，浮动不是噪声开关而是围绕基线的真实呼吸。

## Assumptions

- “骑行端配置页”指现有 Captive Portal 的 cycling 主路径，而不是新建原生 App。
- 三方向先供选择；用户确认后才移植到 `tools/web/ble-monitor.html` 与 `main/web/*`。
- BikePower 暂无独立 logo 资产，方向稿只用文字标识和 BP 简写。
