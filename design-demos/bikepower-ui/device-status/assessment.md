# Pages 设备状态监控：实现链路与布局评审

日期：2026-11-05。范围：当前工作区源码的只读评估，以及独立设计原型。生产固件、Pages、配置与发布状态均未在本轮修改。原型数据全部为设计示例，不构成测量证据。

## 1. 链路结论

现有 Pages 已能连接开发板，并在实时监控、设备比对、通知检查与健康检查之间复用同一 GATT 连接。基础连接成立，但设备资源遥测链路还未实现。现有私有配置服务暴露配置快照与写入事务，没有内存、CPU 使用率或连接 RSSI 的运行快照。[源码：`tools/web/ble-monitor.html` 的 `singleDevice`、`MODE_ROUTES`、`connectSingleWith`；`main/ble_config_service.c` 的服务定义]

内存已由主循环每 10 秒调用 `esp_get_free_heap_size()` 和 `esp_get_minimum_free_heap_size()`，输出到 INFO 心跳；配网 HTTP 的 `/api/mem_stats` 返回 `free` 与 `min_free`。这些不是 BLE 特征，Pages 连接蓝牙后不能直接读取。正式遥测应直接采集状态，不解析日志，也不依赖日志级别。[源码：`main/app_main.c:656-686`；`main/wifi_portal.c:592-598,644`]

CPU 主频配置是 160 MHz；`CONFIG_FREERTOS_USE_TRACE_FACILITY` 与 `CONFIG_FREERTOS_GENERATE_RUN_TIME_STATS` 均未开启。因此现有数据不足以给出 CPU 使用率或任务 CPU 占用。主循环耗时只能表示主循环节拍，不能代替全机 CPU。[源码：`sdkconfig:1424-1426,1671-1674`]

本地 ESP-IDF v5.5.4 的 NimBLE 头文件提供 `ble_gap_conn_rssi()` 和 `ble_gap_conn_find()`，可获取已连接链路的 RSSI、连接间隔、peripheral latency 与 supervision timeout。当前外设 GAP 回调没有采集这些遥测；应用通知路径没有完整统计 mbuf 分配失败或 `ble_gatts_notify_custom()` 的结果。SDK 提供能力，不代表应用已经接入。[源码：`main/ble_bikepower.c:957-965,1074-1124`；本地 SDK `host/ble_gap.h`]

## 2. 指标支持矩阵

| 指标 | 当前实现 | 建议接入 | 界面口径 |
|---|---|---|---|
| 当前空闲堆、启动最低空闲堆 | 已采集，串口 / 配网 HTTP | 低频采集到 BLE 快照 | KiB；最低值按设备启动会话 |
| 最大连续空闲块 | SDK 支持，当前未上报 | `heap_caps_get_largest_free_block()` | 与空闲堆使用相同 capabilities |
| 堆占用比例 | 当前无同口径容量字段 | 同口径 allocated + free 获取容量 | 不能用芯片 400 KiB SRAM 当分母 |
| CPU 主频 | 配置有值 | 实际频率有能力时采样，否则标注配置值 | MHz；与使用率分开 |
| CPU 忙碌比例 | 统计开关关闭 | 第二阶段用窗口内 IDLE / total 计数差 | 未启用时显示“— / 未启用” |
| 每任务 CPU | 未接入 | 第二阶段统计任务运行计数 | 任务合计与 IDLE 口径一致 |
| 任务最低空闲栈 | SDK 支持 | 对已持有句柄的关键任务低频采样 | ESP-IDF API 单位为字节，不再次乘 word 大小 |
| 运行时间、重启原因、运行态 | 可从 SDK / 应用读取，未通过遥测上报 | uptime + boot session + app state | 设备启动与网页重连分开 |
| 板端 RSSI | SDK 支持，当前未采集 | host 上下文低频查询并缓存 | 开发板接收网页信号的强度 |
| MTU、连接间隔、连接延迟、超时 | SDK 支持，当前未统一上报 | GAP 更新时缓存 | 协商值；连接间隔不等于通知周期 |
| 发送失败、mbuf 分配失败、锁竞争跳过 | 当前无完整计数 | 通知路径仅做轻量计数，异步快照 | 应用提交与失败，不声称无线确认 |
| 接收间隔、通知年龄、停更 | Pages 部分已有 | 按特征或统一遥测序号计算 | 网页前台接收时间 |
| 无线真实丢包、PHY 重传率 | 当前链路无充分证据 | 需控制器 / 原生抓包补充 | 不从 JS 间隔或采样序号推导 |
| 上游功率计状态 | `bridge_runtime_snapshot()` 已有 | 单独能力、单独链路快照 | 不与板↔网页 RSSI 混合 |

ESP-IDF 的堆文档明确支持最低值与最大连续块；逐任务堆跟踪具有额外 RAM 和运行开销，不建议作为第一版常驻监控。[官方：ESP-IDF Heap Memory Debugging](https://docs.espressif.com/projects/esp-idf/en/v5.5.4/esp32c3/api-reference/system/heap_debug.html)

## 3. 实现方案比较

| 方案 | 固件开销 / 难度 | 覆盖范围 | 取舍 |
|---|---|---|---|
| **独立只读遥测服务 + 独立设备状态页，推荐** | 小规模快照与低频通知；中等接入量 | 内存、系统、链路，CPU 可选 | 与配置事务隔离；前端探测能力，旧固件自然降级 |
| 在现有配置服务追加运行特征 | 少一个服务定义；需要明确分离运行快照与 revision | 同上 | 易复用已授权服务；配置模块职责容易膨胀 |
| 仅在 Pages 展示现有接收统计 | 不改固件；最简单 | 通知间隔、停更、网页重连 | 无法提供内存、CPU 与可靠板端 RSSI |

推荐以独立「设备状态」页作为持久入口，位于设备工具组，路由建议 `#/device-status`。独立页面比在运动曲线旁堆更多指标更清晰；健康检查继续承担一次性检查与结论报告，设备状态承担持续观察。全页仍沿用一个共享连接。

## 4. 推荐数据流

```mermaid
flowchart LR
    A[主任务：系统与内存低频采样] --> C[固定容量遥测快照]
    B[NimBLE host：RSSI与连接事件] --> C
    C --> D[只读私有 GATT：Read / Notify]
    D --> E[Pages 共享连接：解码与能力探测]
    E --> F[设备状态：趋势与明细]
```

1. 主任务每秒生成系统与内存快照。RSSI 查询交给 BLE host 定时事件，执行后发布缓存；不在 GATT 回调、ISR 或通知定时器里同步执行 HCI 查询。
2. Read 回调只复制快照。Notify 只对订阅的客户端发送；退订与离开设备状态页停止该页遥测订阅，其他工具需要时由订阅管理复用。全局数据采样频率可低于界面刷新频率。
3. 通知分成系统、内存、链路等固定二进制记录，基础记录不超过 20 字节，以支持 ATT MTU 23；不能假定电脑协商大 MTU。
4. 每组携带协议版本、有效位、快照序号；元数据提供 boot session、能力掩码与采样周期。分组记录按同一快照序号组合，缺组标记不完整，不能混合不同时刻数据。
5. CPU 或 RSSI 不支持 / 查询失败时用有效位声明缺失，不用 0 当真值。采样序号按生成快照递增；未订阅与后台期间不参与缺口判断。
6. 历史保留在浏览器固定容量环形缓冲，设备只存最近快照。任务详情按需低频读取，有限条数与固定缓冲；不把全量任务表每秒广播。
7. 新服务候选 UUID 可用 `7a5a1000-4c7a-4f2a-9b3e-6d1f4a8c0b21`，特征用其子段。**这是设计候选，尚未分配或注册**；现有 `0000` 至 `000b` 保持含义。Pages 添加 `optionalServices` 授权；不为诊断服务增加运动广播负担。
8. 元数据提供真实构建版本与板型，不能把可被身份复制覆盖的 DIS 版本当成固件能力证据。不修改 NVS schema，不持久化临时监控状态。

正式实现需设计上下文之间的同步、关闭过程与通知生命周期，避免和当前配置事务或 NimBLE stop/deinit 形成锁循环。

## 5. Mac 参考与布局

## 6. 状态语义与浏览器限制

- **正常**：有效且新鲜的遥测显示当前值。
- **低内存**：复用项目配置的 81920 B（80 KiB）警戒线与 20480 B（20 KiB）严重线。低于阈值才告警，不用通用电脑“内存压力”算法。
- **停更**：依据实际采样周期判断前台数据是否过期；初版建议连续超过三次周期没有完整快照时标记停更。冻结最后值并标记时间；不画伪造的连续线。
- **暂停画面**：仍保持连接和后台采样。继续时回到最新值，与“释放连接”区分。
- **旧固件**：GATT 已连接但未发现遥测服务 / 能力，显示升级提示，运动监控照常可用。
- **未连接**：实时值清空，历史与报告应另标为结束会话。
- **网页后台**：暂停健康判定，恢复后开启新观测窗口；浏览器调度延迟不能算成无线丢包。
- **重启与重连**：网页重连不重置设备最低空闲堆；boot session 改变才划分新设备运行会话。
- **唯一连接**：当前 peripheral 只有一个客户端槽位；网页监控期间无法同时连接骑行 App / 码表。页面明确提供释放，实际释放时也需解绑该设备的 inspector / compare 订阅并更新共享状态。
- **浏览器**：HTTPS Pages 满足安全上下文要求，但仍需用户点击授权。Mac Chrome / Edge 可作为入口，Safari 和 Firefox 不支持这条标准 Web Bluetooth 链路；手机端不能只因布局能打开就声称蓝牙可用。[MDN：Web Bluetooth API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Bluetooth_API)

## 7. CPU 第二阶段与资源约束

准确忙碌比例可按一个窗口内的 `1 - Δidle_runtime / Δtotal_runtime` 计算，需处理首样本、计数回绕、重启与分母为零。任务占用同样使用窗口增量，不能直接显示累计百分比。

启用 FreeRTOS runtime stats / trace 需要评估构建尺寸、每任务统计字段、计数精度及调度影响。本地 SDK 文档提示 `uxTaskGetSystemState()` 在读取全任务时会暂停调度，不能当作无成本每秒扫描。优先检查是否能用 IDLE 计数 getter 和已注册任务句柄取值，再决定是否开放完整任务表。

新增缓冲、RSSI 查询与 CPU 统计的 RAM / CPU 成本目前没有实测，不能宣称开销为零或已经满足 >80 KiB 空闲堆要求。第一阶段目标是固定容量与低频采样，先守住 BLE 通知和共存的资源余量。

## 10. 离线交互迭代：常驻与窗口监控

根据布局评审反馈，增加页面常驻指标栏。滚动页面时，内存余量、CPU 能力与 RSSI 仍可见，点击指标打开对应详情窗口。原来的资源分类与明细区继续保留。

详情使用页面内独立浮动窗口，不打开浏览器弹出窗口。桌面支持标题栏拖动、右下角调整大小、折叠、放大与还原、关闭；小屏适配为浮层。窗口可独立切换内存 / CPU / 蓝牙与时间范围；蓝牙详情同时展示 RSSI 和通知接收间隔。窗口与页面共用同一份演示采样，不重复建立连接。

每秒推进一份确定性演示快照，并保留至多 301 个样本。暂停页面只冻结页面及常驻栏，详情窗口仍更新；暂停窗口只冻结窗口，页面仍更新；继续时回到最新快照。遥测中断场景保留最后值并增加数据年龄，曲线末尾留空；旧固件与未连接不生成有效遥测。切换场景重建演示历史，不将不同场景混为真实会话。

内存用绿色、CPU 用琥珀色、蓝牙用蓝色突出；内存低于 80 KiB、CPU 规划高负载与弱信号使用异常强调。新增 CPU 高负载规划与弱信号场景，用于评审颜色表现，不改变固件能力结论。CPU 默认仍未启用，高负载场景显式开启规划演示。

动画覆盖采样脉冲、数值更新与窗口进入，支持 `prefers-reduced-motion`。浏览器后台暂停演示推进，不把调度延迟计入蓝牙质量。数据、资源和脚本全部本地，无外部字体、图表库、网络请求或真实蓝牙操作。此轮仍采用静态检查，不声称已完成浏览器视觉验收。

## 11. 百分比优先的指标呈现

最新原型默认启用 CPU **演示**，打开页面即可观察百分比变化；这不改变前述固件运行统计尚未开启的事实。按钮仍可模拟“CPU 能力未启用”的降级界面。

内存主读数与常驻栏显示空闲百分比，附带空闲字节数、最低空闲值和连续块大小。内存空闲 / 已用采用分段条，曲线纵轴统一 0–100%；最大连续块曲线同样除以总堆容量，表示可一次分配空间占总堆的比例。它是空闲空间的子集，不与空闲比例相加。示例总堆容量为 320 KiB，现有 80 KiB 警戒线对应示例的 25%；正式阈值仍以字节值为准，不能为不同固件固定成 25%。

CPU 显示忙碌 / 空闲百分比、分段条、0–100% 时间曲线，以及按同一总 CPU 时间口径展示的逐任务水平占用条。任务忙碌占比与 IDLE 空闲占比合计约 100%，展示舍入可能存在微小差异。80% 高负载提示仅为原型演示规则，尚未作为固件告警标准。

蓝牙 RSSI 保留 dBm，通知间隔保留 ms；没有充分依据时不编造“蓝牙质量百分比”。页面、详情窗口和手机单文件版同步使用相同数据与占比口径。
