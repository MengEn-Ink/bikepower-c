# BikePower 真实功率桥接配置页 · 原型契约

日期：2026-11-04

状态：高保真前端原型，不连接固件后端，不代表真机数据。

## 1. 页面目标

在现有骑行配置首页内完成两类输出的切换：

- 模拟输出：沿用固定、配速机器人、自定义三种模式。
- 真实功率计：绑定一个 BLE 功率计，同时桥接其真实功率和 CPS 曲柄数据计算出的真实踏频。

真实功率计模式不允许选择独立踏频设备，也不允许用模拟踏频补位。设备不提供曲柄数据时，页面明确显示“未提供踏频”，保存后对外停止踏频字段。心率仅保留模拟或关闭。

## 2. 信息层级

移动端顺序：

1. 配网剩余时间与当前输出状态。
2. 功率来源切换。
3. 实时功率、校正后输出、真实踏频和模拟心率。
4. 来源设备与扫描入口。
5. 功率校正。
6. 模拟心率。
7. 断线保护与监测详情。
8. 保存和关闭 WiFi。

桌面端：

- 左列固定为实时证据，包含当前输出、两侧连接状态和数据新鲜度。
- 右列承载来源、设备、校正、心率及保存操作。
- 不把配置区拆成大量悬浮卡片，以结构线和完整区段建立层级。

## 3. 关键状态

| 状态 | 功率 | 踏频 | 页面反馈 |
|------|------|------|----------|
| 数据有效 | 原始值与校正后值 | 同源真实 rpm | 绿色状态点、字段年龄 |
| 设备仅提供功率 | 正常桥接 | 不输出 | “此功率计未提供踏频” |
| 数据过期 | 归零 | 失效 | 持续警告，不保留旧值 |
| 重连中 | 归零 | 失效 | 重连倒计时与停止入口 |
| 模拟输出 | 模拟功率 | 模拟踏频 | 明确标注“模拟” |
| 心率关闭 | 不受影响 | 不受影响 | HRS 与 FTMS 心率字段停止 |

## 4. 交互语义

- 来源切换只修改草稿，保存后才改变实际输出。
- 扫描只列出 CPS 功率计，候选项显示“功率＋踏频”或“仅功率”。
- “选择并测试”建立短时预览；测试结果不会自动替换正在运行的来源。
- 校正提供原值、瓦数、百分比三种互斥模式；实时输出与草稿预览必须分开。
- 瓦数校正范围 -200 至 +200 W；百分比范围 -50% 至 +50%。
- 选择“仅功率”设备后持续提示保存结果不含踏频，不自动回退模拟。
- 停止桥接需要页内二次确认；功率立即归零，真实踏频立即失效。
- “保存并关闭 WiFi”使用页内确认，说明桥接继续而网页将不可访问。
- 原型提供正常、数据过期和重连中三种状态切换，入口放在监测详情内并标记为演示。

## 5. 视觉与可访问性

- 完整继承 `01 · 信号宣言`：深黑、锈橙、纸白、严格网格和 Bodoni 大数字。
- 所有示例数值明确标注“演示数据”，不冒充设备实测。
- 触控目标最小 44px；表单文字最小 16px；键盘焦点可见。
- 状态始终使用文字、图形和颜色三重表达。
- 读数使用稳定宽度和等宽数字，轮询时不推动布局。
- 手机宽度 375px 起可用；桌面 960px 起转为双列。

## 6. 文件边界

- `mock.js`：唯一演示数据源和初始状态。
- `api.js`：异步 API stub，模拟扫描、测试、保存、停止桥接和关闭 WiFi。
- `app.js`：草稿、渲染、状态切换与页面交互。
- `index.html` / `styles.css`：结构和主题。

原型不修改 `main/web/`，后续生产化时需重新对接真实 API、状态轮询、NVS schema、BLE codec 和协议门禁。
