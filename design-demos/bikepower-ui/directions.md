# BikePower UI · 六个方向候选

## 01 · 最佳设计师｜Experimental Jetset × Distance Manifesto

- 借的是什么：把单一事实放到极大，把解释压到规则线与小字；用严格网格而不是卡片堆叠。
- 主角素材：功率数字与三路信号曲线。
- 骨架：监控端左侧状态栏 + 中央巨大功率 + 右侧异常证据；配置端是“目标基线”纵向编辑流。
- 胆量花在哪：258W 作为占屏主角。
- form 来自内容：功率是骑行仿真的主输出，页面也由功率统领。

## 02 · 最佳设计师｜Teenage Engineering 工业控制思维

- 借的是什么：每个控件像有明确用途的硬件面板，颜色只标状态，旋钮/轨道表现范围。
- 主角素材：程序化功率轨道与物理式控制台。
- 骨架：桌面工作台横向分区；移动端按“输出—浮动—广播—保存”排成一台掌上控制器。
- 胆量花在哪：把数据控制与硬件面板做成同一种语法。
- form 来自内容：BikePower 是一块真实开发板，界面应像操作设备而不是操作 SaaS。

## 03 · 现实参照｜Grafana Panels

- 参照：Grafana 官方 Dashboards 文档，参考板 `refs/grafana-docs.png`。
- 借的是什么：相关面板成组、标题明确、状态一眼扫完，二级信息可以下钻。
- 主角素材：多面板实时数据网格。
- 骨架：顶部健康总览，下面按信号/设备/事件三组 panels。
- 胆量花在哪：几乎不做装饰，把密度本身做成秩序。
- form 来自内容：BLE 通知天然就是多个相关数据源的统一观测。

## 04 · 现实参照｜Wahoo 传感器短路径

- 参照：Wahoo 官方 Pair a sensor 流程，参考板 `refs/wahoo-pairing.png`（页面受到安全验证遮挡，流程事实以官方文本为准）。
- 借的是什么：设备入口明确、配对动作短、选择后确认，不把高级配置混进连接主路径。
- 主角素材：当前目标与一个明确主动作。
- 骨架：移动优先三步配置；监控端也压缩为连接—读取—报告。
- 胆量花在哪：主动隐藏低频 GATT 细节，按需展开。
- form 来自内容：热点配网有倒计时，流程必须短。

## 05 · 秒数轮盘 Web 07｜Cosmic Retro-Futurism

- 来源：本轮秒数 46 → Web `46 % 20 + 1 = 07`，样张 `web/07-cosmic-retro-futurism.jpg`。
- 借的是什么：三色、轨道线、古典数字与技术注记并置。
- 主角素材：三条信号像轨道绕着目标功率运行。
- 骨架：左侧观测说明，右侧轨道式实时图；配置用同心范围环。
- 胆量花在哪：把“浮动范围”直接画成轨道宽度。
- form 来自内容：功率、踏频、心率不是独立随机数，而是耦合运行的轨道。

## 06 · 秒数轮盘 East 11｜佐藤可士和极简符号

- 来源：本轮秒数 46 → East `46 % 12 + 1 = 11`，样张 `east/11-sato-minimal-symbol.jpg`。
- 借的是什么：一个符号占半屏、最多三色、另一半是极清楚的信息与动作。
- 主角素材：大写 `W` 与锈橙功率块。
- 骨架：桌面 52/48 对分；手机把大符号缩成顶部状态板。
- 胆量花在哪：几乎删除所有容器，只靠比例和线。
- form 来自内容：W 是目标功率的单位，也是产品最短的识别符号。
