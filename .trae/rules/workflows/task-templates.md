> 本文件给出提交、PR、Issue 三类常用模板的使用说明。模板内容偏短，重点是保持与项目规则一致。

## Commit Message 模板

- 标题格式：
`<type>(<scope>): <简体中文概述>`
- 正文要求：
逐文件列出变更，格式为 `文件名：变更内容`
- 结尾必须附：
```text
Co-authored-by: AI <ai@trae>
Model: {模型名}/{版本号}
```

### 示例

```text
feat(wifi): 补齐配网门户治理规则

.trae/rules/domain/wifi.md：新增配网实现边界、表单字段与路由规则
.trae/rules/workflows/device-testing.md：补充真机测试步骤与通过标准
.trae/README.md：补充 .trae 目录结构说明

Co-authored-by: AI <ai@trae>
Model: GPT-5.4
```

## PR 模板说明

- 标题：与核心 commit 或功能主题保持一致
- 正文至少包含：
- 变更目的
- 影响范围
- 验证结果
- 风险与未覆盖项

### 推荐结构

```markdown
## 背景
[为什么要改]

## 变更
- [关键改动 1]
- [关键改动 2]

## 验证
- [运行了什么测试]
- [未运行什么测试以及原因]

## 风险
- [潜在回归点]
```

## Issue 模板说明

- 用于描述 bug、功能需求、治理缺口或测试缺口
- 最少包含：
- 现象或目标
- 影响范围
- 预期行为
- 验收标准

### 推荐结构

```markdown
## 问题/目标
[一句话描述]

## 背景
[出现条件、现有实现、约束]

## 影响范围
- [模块或文件]

## 验收标准
- [可验证结果 1]
- [可验证结果 2]
```

## 使用要求

- `TT-1`：模板只提供结构，不替代实际测试记录
- `TT-2`：提交、PR、Issue 中的数字、脚本名、版本号必须与当前仓库一致
- `TT-3`：不要把无关文档、代码、规则混在同一个提交主题里
