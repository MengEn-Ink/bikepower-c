# Entropy 治理规则（C / ESP-IDF 版）

<!-- stability: tier-2 (稳定，随治理策略变更) -->
<!-- rule-id-prefix: EG (引用格式: EG-N，如 EG-1文档Drift) -->
> Agent 生成的代码会积累技术债，定期扫描清理。
> 命名规范以 coding-style.md 为准，常量以 config 头文件为准。

---

## 扫描时机

每次版本发布前（git tag 前），必须执行以下扫描。

## 检查项

### 1. 文档 Drift

文档与代码实际行为是否一致：

| 检查方法 | 通过标准 |
|---------|---------|
| 对比 PROGRESS.md 阶段进度与实际代码完成度 | 一致 |
| 对比 config 头文件常量值与 README.md / docs 中引用的值 | 数值一致 |
| 对比 general-rules.md 文件结构树与实际目录 | 一致 |

### 2. 命名漂移

命名是否符合 [coding-style.md](../coding-style.md)：

| 检查方法 | 通过标准 |
|---------|---------|
| 文件名是否 `snake_case.c` / `snake_case.h` | 全部符合 |
| 宏/常量是否 `UPPER_SNAKE_CASE` | 全部符合 |
| 类型是否 `snake_case_t` | 全部符合 |
| 函数是否 `<模块>_<动作>` | 全部符合 |
| 内部静态变量是否 `s_` 前缀、静态函数是否仅模块私有 | 全部符合 |
| 日志 TAG 是否模块大写简称 | 全部符合 |

### 3. 死代码

| 检查方法 | 通过标准 |
|---------|---------|
| 未被任何文件包含的 .c/.h | 无（或已删除） |
| 未被调用的函数 | 无（或已标记待删除） |
| 未被引用的 config 头文件常量 | 无（或已删除） |
| 未被使用的 include | 无 |

### 4. 规则腐烂

`.trae/rules/` 中是否有过时内容：

| 检查方法 | 通过标准 |
|---------|---------|
| general-rules.md 文件结构 / 模块依赖图是否与实际一致 | 一致 |
| hardware-constraints.md 参数是否与 config 头文件一致 | 一致 |
| 各规则引用的文件名 / 函数名是否仍存在 | 一致 |

### 5. 配置一致性

| 检查方法 | 通过标准 |
|---------|---------|
| `bikepower_config.h` 与 `domain_config.h` 中重叠常量（POWER_MIN/MAX、CADENCE、HR、POWER_STEP_W、默认值）是否一致 | 一致 |
| 领域层范围校验（profile.c / power_engine.c）是否与 domain_config.h 一致 | 一致 |
| 配网表单 min/max 是否与 config 头文件一致 | 一致 |
| BLE UUID 是否无冲突 | 无冲突 |

### 6. 记忆清理

`.trae/memory/project-context.md` 是否有过时或冗余内容：

| 检查方法 | 通过标准 |
|---------|---------|
| 已验证决策是否仍与当前代码一致 | 一致或已删除 |
| 是否有重复的踩坑记录 | 无重复 |
| 是否有可提炼为 `.trae/rules/` 通用规则的条目 | 已提炼或保留理由充分 |

## 扫描报告格式

扫描结果记录到 CHANGELOG.md 版本条目中：

```

- 规则腐烂: ✅/❌ (说明)
- 配置一致性: ✅/❌ (说明)
- 记忆清理: ✅/❌ (说明)
```
