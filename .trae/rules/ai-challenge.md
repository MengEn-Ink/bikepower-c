# AI 质疑规则

<!-- stability: tier-1 (治理原则不变) -->
<!-- rule-id-prefix: AC -->
> AI 不应谄媚用户，发现方案漏洞时必须主动提出。

## 质疑触发条件

### 1. 硬件约束冲突
ESP32-C3 硬约束冲突必须指出并给替代方案：
- WiFi 与 BLE 同时运行 → 指出 RF 互斥，建议软切换 + 重启。
- 内存超限（空闲堆 < 80KB）→ 指出风险，建议优化。
- ISR 内调用阻塞/BLE/日志 API → 指出中断上下文限制。

### 2. 跨模块影响
修改可能影响其他模块时必须提醒影响范围：
- 修改 `bikepower_config.h` 常量 → 列出所有引用模块。
- 修改 BLE 通知格式 → 列出依赖的骑行 App。
- 修改按钮阈值 → 确认与 config 头文件一致。
- 修改 NVS schema → 确认迁移方案（阶段4）。

### 3. 更优方案
存在更优方案时给 2-3 个选项 + 权衡分析（实现复杂度/内存/可维护性/风险），并给推荐及理由。

### 4. 安全风险
| 风险 | 级别 | 缓解 |
|------|------|------|
| WiFi AP 无密码 | 中 | 配网模式短暂开放 + 超时自动关闭 + 重启 |
| 配置明文存储 | 中 | 已知限制 |
| BLE 无配对验证 | 低 | 模拟器场景可接受 |
| Web 输入注入（XSS） | 高 | 配网页面输出转义（阶段5） |

## 质疑输出格式
```
⚠️ 质疑：[问题]
原因：[为什么有问题]
影响：[受影响模块/功能]
建议：
1. [方案 A]
2. [方案 B]
```

## 不质疑的情况
- 用户明确说"就这样做"后，不再质疑同一问题。
- 纯风格偏好。
- 已在 PROGRESS.md / docs 中记录的已知限制。

## 操作权限分类
| 级别 | 操作 | 执行方式 |
|------|------|---------|
| Allow（自动） | 低风险可逆 | lint/格式化/编译 | 直接执行 |
| Ask（确认） | 中风险 | WiFi 启动、功率调整、config 修改 | 列影响后等确认 |
| Deny（禁止） | 高风险不可逆 | 开机自启 WiFi、BLE+WiFi 共存、绕过内存限制 | 拒绝 + 给替代方案 |
