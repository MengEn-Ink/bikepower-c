# OTA 固件升级操作手册

> 适用固件：v3.1.5 及以上
> 适用读者：测试人员、最终用户、技术支持
> 更新日期：2026-06-27

---

## 一、功能概述

BikePower C 支持通过 WiFi 配网页面无线升级固件（OTA），无需 USB 数据线连接电脑。升级流程内置防降级保护和自检回滚机制，确保升级失败时设备不会变砖。

### 核心特性

| 特性 | 说明 |
|------|------|
| 无线升级 | 通过 WiFi 配网页面上传固件 bin 文件 |
| 防降级 | 拒绝低于当前版本的固件（基于版本号比较） |
| 同版本重刷 | 允许上传相同版本固件（修复/重置场景） |
| 自检回滚 | 新固件启动 10s 内若 BLE 初始化失败，自动回滚到上一版本 |
| 流式写入 | 固件分块写入 Flash，不整包驻留内存（峰值 ~4KB） |

## 二、前置条件

| 项目 | 要求 |
|------|------|
| 设备版本 | v3.1.5 及以上（已含 OTA 功能） |
| 固件文件 | 从开发者获取的 `bikepower-c.bin`（约 1MB） |
| 手机/电脑 | 支持 WiFi 连接 + 浏览器 |
| 设备电量 | 已通电运行（USB 供电或电池） |

## 三、升级操作步骤

### 步骤 1：进入配网模式

1. 确保设备已通电，LED 处于呼吸/常亮状态（BLE 活动态）。
2. **长按按钮 2 秒以上**，LED 切为快闪（进入二次确认窗口）。
3. **3 秒内再按一次按钮**，LED 熄灭，设备进入 WiFi 配网模式。
4. 设备启动 SoftAP，SSID 为 `BikePower`，密码 `12345678`。

> 超时提示：确认窗口 3 秒内未再按按钮则自动取消，回到 BLE 活动态。

### 步骤 2：连接设备 WiFi

1. 打开手机/电脑的 WiFi 设置。
2. 找到网络 `BikePower`，输入密码 `12345678` 连接。
3. 连接成功后，**手机通常会自动弹出配网页面**（Captive Portal）。
   - 若未自动弹出，手动打开浏览器访问 `http://192.168.4.1`。

### 步骤 3：上传固件

1. 在配网页面点击**"更多配置"**或直接访问**"固件升级"**入口。
2. 进入固件升级页面，点击**"选择文件"**。
3. 选中开发者提供的 `bikepower-c.bin` 固件文件。
4. 点击**"开始升级"**。

### 步骤 4：等待升级完成

1. 页面显示上传进度，上传完成后设备自动校验并写入 Flash。
2. 校验通过后设备**自动重启**，页面显示"升级成功"。
3. 设备重启后进入新固件，LED 恢复正常呼吸/常亮。

> 全程预计 30-60 秒（取决于文件大小和 WiFi 传输速度）。

### 步骤 5：验证升级结果

1. 设备重启后，BLE 广播名称仍为 `BikePower`。
2. 用骑行 App 连接设备，确认数据正常推送。
3. （可选）通过串口查看启动日志确认版本号。

## 四、防降级规则

| 场景 | 设备行为 | 页面提示 |
|------|---------|---------|
| 上传版本 > 当前版本 | 正常升级，重启进新固件 | "升级成功" |
| 上传版本 = 当前版本 | 正常重刷，重启进同版本 | "升级成功" |
| 上传版本 < 当前版本 | **拒绝升级**，设备不变 | "升级失败" |

版本号格式：`vMAJOR.MINOR.PATCH`（如 `3.1.5`），逐段比较。

## 五、自检与回滚机制

新固件首次启动时处于待确认状态（PENDING_VERIFY）：

```
新固件启动
  ├─ BLE 初始化成功 → 10s 自检窗口到期 → 确认有效（VALID）→ 正常运行
  └─ BLE 初始化失败 → 立即标记无效 → 自动回滚到上一固件
```

- 自检窗口 10 秒，期间 BLE 正常工作则到期自动确认。
- 若 BLE 起不来，设备自动回滚，下次启动回到上一版本。
- 用户无需干预，回滚后设备可正常使用旧版本。

## 六、常见问题排查

### Q1：手机连上 BikePower WiFi 后没有自动弹出网页

**可能原因**：部分手机系统 Captive Portal 检测被关闭或延迟。

**解决方法**：
1. 手动打开浏览器，访问 `http://192.168.4.1`。
2. Android 用户可尝试关闭再开启 WiFi 重触发检测。
3. iOS 用户可尝试在 WiFi 设置页点击设备名称旁的"i"。

### Q2：上传固件后页面一直转圈/超时

**可能原因**：WiFi 共存模式下传输速度受限，大文件传输偶发超时。

**解决方法**：
1. 等待 60 秒，设备可能仍在后台写入。
2. 若超时失败，刷新页面重新上传。
3. 确保上传期间手机不要切换到其他 WiFi。

### Q3：升级后设备无法启动 / LED 异常

**可能原因**：新固件自检失败已自动回滚，或固件文件损坏。

**解决方法**：
1. 等待 15 秒，设备可能正在回滚并重启。
2. 若仍无响应，拔插 USB 重新通电。
3. 设备应自动回到上一可用版本。若仍不行，联系开发者通过 USB 重新烧录。

### Q4：页面提示"升级失败"（版本过低）

**原因**：上传的固件版本低于设备当前版本，被防降级保护拒绝。

**解决方法**：
1. 确认固件文件版本号是否正确。
2. 向开发者索取等于或高于当前版本的固件。

### Q5：配网模式 180 秒后自动退出

**原因**：配网模式有 180 秒超时保护，超时后自动关闭 WiFi 回到 BLE。

**解决方法**：重新长按按钮进入配网模式即可。

### Q6：升级过程中断电会怎样

**影响**：Flash 写入中断，新固件不完整。

**设备行为**：
- 重新上电后，bootloader 检测到新固件未确认（PENDING_VERIFY），自动回滚到上一版本。
- 设备可正常启动旧版本，不会变砖。

## 七、技术规格

| 项目 | 规格 |
|------|------|
| 固件分区 | ota_0 / ota_1 双分区互切，各 1.75MB |
| 上传协议 | HTTP multipart/form-data，流式写入 |
| 版本校验 | esp_app_desc_t.version 与 FIRMWARE_VERSION 宏比较 |
| 回滚机制 | ESP_OTA_IMG_PENDING_VERIFY + 10s 自检窗口 |
| Flash 布局 | 4MB（nvs + phy + ota_0 + ota_1 + otadata + coredump） |
