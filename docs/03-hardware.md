# BikePower C 硬件指南

这份文档面向开发者和 DIY 骑行爱好者，重点说明推荐开发板、引脚用途、接线思路、供电建议和常见硬件问题。它不替代原理图，但可以作为快速搭建和排查的参考。

## 1. ESP32-C3 开发板型号推荐

当前项目推荐使用合宙 ESP32-C3 开发板，也已适配 M5Stamp C3。原因很直接：

- 生态成熟，资料多，买起来方便
- USB 供电和下载调试都比较直接
- 体积适合做小型骑行附件
- 足以覆盖 BikePower C 当前的 BLE + WiFi 配网需求

如果你使用其他 ESP32-C3 板卡，也可以移植，但要先核对按钮、LED、串口和供电相关引脚是否一致。

## 2. 引脚定义表

| 引脚 / 接口 | 默认用途 | 说明 |
|------|------|------|
| `GPIO9` / `GPIO3` | 按钮输入 | 通用板用 `GPIO9`，M5Stamp C3 用 `GPIO3`；内部上拉，按下为低电平 |
| `GPIO12` / `GPIO2` | LED 输出 | 通用板用 `GPIO12` 普通 LED，M5Stamp C3 用 `GPIO2` SK6812 RGB LED |
| `USB / 5V` | 供电与下载 | 最常用的供电和烧录入口 |
| `3V3` | 板载逻辑电源输出 | 可给少量低功耗外设供电 |
| `GND` | 公共地 | 外设接入时必须共地 |
| `UART0` | 调试串口 | 用于日志查看、烧录和故障定位 |

![硬件引脚对照](images/hardware-pinout.png)

说明：

- 当前固件明确用到的核心 GPIO 是按钮和 LED 两类，实际引脚由板型检测决定
- 板型检测读取 `GPIO12`：通用板读高，M5Stamp C3 悬空读低
- `UART0` 主要给开发调试使用，不建议在成品化前随意复用
- 供电和外设接入前，先确认板卡丝印和原厂资料

## 3. 接线示意图

仓库中已经提供了架构和状态机 SVG 图，适合配合本说明一起看。这里给一个文字版接线思路，方便快速搭建：

- 通用板按钮一端接 `GPIO9`
- M5Stamp C3 使用板载 `GPIO3` 按钮
- 按钮另一端接 `GND`
- 通用板状态 LED 控制脚接 `GPIO12`
- M5Stamp C3 使用板载 `GPIO2` SK6812 RGB LED
- LED 供电方向按你所用板卡或模块实际极性处理
- 开发板通过 USB 接电脑时，可同时完成供电、烧录和串口日志查看
- 如果接外部电源，注意与开发板地线保持共地

对大多数开发板来说，最省事的方式是直接使用板载按钮和板载 LED；如果你要做外置按钮或外置指示灯，再额外引出对应引脚。

## 4. 功率计安装建议

BikePower C 的核心价值在于模拟和广播骑行数据，因此安装方式更多取决于你的整车和训练场景。对于牙盘或曲柄附近的安装，建议优先考虑下面几点：

- 设备固定要牢，避免踩踏震动导致松脱
- 尽量避开脚跟、鞋底和曲柄旋转扫过的区域
- 外壳或固定支架要考虑防汗、防水雾和防泥点
- 如果放在中轴、牙盘或曲柄附近，注意不要影响链条和脚踏动作
- 蓝牙信号不要被大面积金属结构完全遮挡

如果你只是做室内训练台模拟器，最简单的方法通常是把设备固定在车把附近、车架上管附近，或者训练台旁边。

## 5. 功耗估算与供电建议

基于当前项目约束，可以先用工程化思路估算：

- 设备在 BLE 工作时，整体功耗相对较低
- 进入 WiFi 配网时，功耗和内存占用都会比纯 BLE 状态更高
- 长时间骑行建议优先选择稳定外接电源，而不是只靠小电池硬撑

供电建议：

- 日常开发：直接 USB 供电最稳妥
- 车上长期使用：建议用稳压后的 5V 方案
- 使用移动电源时，优先选择不会因小电流自动关机的型号
- 如果要上电池方案，必须额外评估续航、充电安全和电压稳定性

如果现场出现随机重启、连接不稳、保存配置失败，先排查供电质量，再怀疑软件问题。

## 6. 扩展接口说明

当前固件主要聚焦 BLE、按钮、LED 和 WiFi 配网，仍适合预留扩展接口给后续 DIY：

- `I2C` 预留：适合接小屏幕、传感器、EEPROM 等
- `SPI` 预留：适合接显示模块、外部高速外设
- `UART0` 调试：建议保留，方便后续抓日志

扩展时建议遵守两个原则：

- 不要占用已经用于按钮和 LED 的默认引脚
- 新增外设前，先核对 ESP32-C3 板卡可用 GPIO、启动脚限制和供电余量

## 7. 常见硬件故障排除

### 设备完全不亮

先检查 USB 线是否支持数据传输，再检查供电是否稳定。如果是外接电源，确认电压和极性没有接错。

### 能上电但没有蓝牙广播

先看 LED 是否有慢闪提示；如果没有，建议接串口查看启动日志，确认固件是否正常运行。

### 按钮没反应

重点检查 `GPIO9` 是否接对，按钮另一端是否真正接地；如果用了外接按钮，还要排查接触不良和焊点虚焊。

### LED 显示异常

确认 `GPIO12` 的接法和 LED 极性是否匹配。当前逻辑是高电平点亮，如果你使用的是不同接法的外置 LED，可能需要重新核对驱动方式。

### 配网时设备不稳定

先检查供电是否足够，因为 WiFi 配网阶段比纯 BLE 更吃资源；再确认周围无线环境是否过于拥挤。

### 烧录或串口日志打不开

先确认 USB 驱动、线材和端口占用情况，再检查是否选错了串口设备。开发阶段建议始终保留 UART0 调试链路。
