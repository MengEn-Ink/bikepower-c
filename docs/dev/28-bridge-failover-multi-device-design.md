# 桥接自动恢复与多设备备选设计

> 日期：2026-11-05
> 状态：实现与离线验证已完成，实物验收待补齐
> 范围：真实功率桥接的冷启动恢复、异常重连、模拟降级、三设备备选与 Portal 管理
> 当前治理结果见 [仓库治理报告](31-repository-hygiene-report.md)，上一轮源码证据见 [清理报告归档](../archive/30-local-cleanup-verification-report.md)；实施步骤已 [归档](../archive/18-bridge-failover-multi-device-implementation-plan.md)。

## 1. 背景

本需求实施前的单设备桥接支持地址定向连接、会话内限时重连、过期归零和功率校正。本设计针对以下历史缺口实施三设备主备恢复；这些条目不代表当前代码仍未实现：

1. 冷启动恢复配置后不会自动发起真实功率桥接。
2. 异常断开只在 60 秒窗口内重试同一设备，窗口耗尽后停止，不会继续低频恢复。
3. 桥接无有效样本时输出 0 W，不会在多次失败后自动降级为模拟数据。
4. 配置只能保存一台功率计，不能把已连接设备作为备选来源。
5. 多设备场景尚未定义优先级、校正归属、配置迁移和用户反馈。

现有 `power_bridge_correct()` 已保证原始功率小于等于 0 W 时直接输出 0 W，并已有宿主机单测与真机 E2E 覆盖。本设计保留该算法，只扩大回归范围。

## 2. 目标

- 已保存真实来源时，设备重启后自动定向连接，不依赖 Portal 或后台扫描。
- 异常断连后记住设备并自动恢复；主设备不可用时尝试备选设备。
- 快速恢复耗尽后保持用户的真实来源配置，但运行时连续输出模拟数据。
- 模拟降级期间低频轮转尝试已保存设备，恢复后自动切回真实数据。
- 最多保存 3 台功率计，按最近成功设备优先。
- 三台设备共用一组功率校正参数。
- 真实输入为 0 W 时，所有校正模式都必须输出 0 W。
- 保持 ESP32-C3 WiFi/BLE 共存、空闲堆大于 80 KiB 和 ISR/回调安全约束。

## 3. 非目标

- 不在开机或恢复阶段扫描附近设备。
- 不通过名称猜测设备身份；身份仍由地址类型和地址共同确定。
- 不支持超过 3 台设备或动态分配设备表。
- 不为每台设备保存独立校正参数。
- 不平滑混合模拟功率和真实功率。
- 不改变对外 CPS、CSC、HRS、FTMS 测量数据格式。
- 不接入 FTMS 骑行台、独立踏频计或真实心率带。

## 4. 已确认决策

| 项目 | 决策 |
|------|------|
| 失败降级 | 只切换运行时实际来源，不覆盖持久化真实来源配置 |
| 降级后恢复 | 每 60 秒定向尝试一台已保存设备，按列表轮转 |
| 设备容量 | 固定 3 台 |
| 尝试优先级 | 最近成功设备优先，其余按用户顺序 |
| 校正参数 | 所有设备共用 |
| 实现边界 | 新增纯 C 主备协调层，保留单设备 BLE 会话层 |
| 后台发现 | 禁止；只允许对已保存地址发起定向连接 |

## 5. 架构

### 5.1 单设备 BLE 会话层

`ble_power_bridge.c` 继续只负责一台明确设备：

- 定向连接地址。
- 发现 CPS 与 Measurement 特征。
- 写入 CCCD 并接收通知。
- 读取设备名称与 DIS 信息。
- 判断两份样本有效、样本过期和无通知超时。
- 清理旧代次回调和连接资源。

会话层不保存设备列表，不决定下一台候选，也不决定何时使用模拟输出。它向协调层暴露当前候选、连接阶段、终止原因、样本有效性和是否达到终态。

### 5.2 主备协调层

新增纯 C 协调层，职责如下：

- 读取最多 3 台设备和最近成功提示。
- 生成快速恢复和低频恢复的候选顺序。
- 接收单设备会话结果并决定继续当前设备、切换候选或进入模拟降级。
- 区分“用户配置来源”和“运行时实际来源”。
- 管理手动扫描期间的暂停与恢复。
- 只输出动作和状态，不直接调用 NimBLE、NVS、日志或 HTTP。

协调层仅由应用主任务调用，不增加跨任务锁。NimBLE 回调仍通过现有受保护会话快照与主任务交互。

### 5.3 配置模型

桥接持久配置分为两部分：

1. 全局设置：用户来源意图、校正模式、瓦数偏移、百分比。
2. 设备表：最多 3 个设备条目，每项包含有效位、地址类型、6 字节地址和名称。

设备槽位 0 是用户首选设备。最近成功设备是独立运行提示，不改变设备表顺序。候选排序规则为：

1. 最近成功设备仍存在于设备表时先尝试。
2. 按槽位顺序尝试其余设备。
3. 同一设备在一轮内只出现一次。

设备去重必须同时比较地址类型和地址。名称只用于展示，不能参与身份匹配。

## 6. 持久化与协议兼容

### 6.1 配置 schema

- `CONFIG_VERSION` 从 13 升到 14。
- schema 13 迁移到 14 时，现有单设备绑定进入槽位 0，其他槽位为空。
- 未绑定或无效旧配置继续恢复模拟来源。
- v14 校验删除无效条目、删除重复条目并压紧列表。
- 设备表为空时，真实来源意图必须校正为模拟来源。

### 6.2 NVS

- `bridge` blob 升为 wire v2，保存全局设置和 3 个设备条目。
- 解码器继续接受 wire v1，并迁移为单设备列表。
- wire v2 的整体版本、长度或字段边界非法时，恢复模拟来源并记录限频警告。
- 单个条目地址类型、空地址、名称或重复身份非法时，只丢弃该条目并保留其他合法条目。

最近成功提示使用独立 NVS 运行元数据，保存地址类型和地址：

- 只有新的设备连续两份 CPS 样本有效，且身份与已保存提示不同时才写入。
- 写入失败不影响当前桥接，不改变配置 revision，也不在每个主循环 tick 重试。
- 提示与当前设备表无法匹配时，忽略提示并从槽位 0 开始。

### 6.3 BLE 配置服务

现有单个桥接配置最多 47 B，当前配置组上限为 48 B，不能把三台设备直接拼入一个特征。

设计保持 `BLE_CONFIG_GROUP_MAX_LEN = 48`：

- 原桥接组继续承载全局校正和槽位 0。
- 新增备选槽位 1 配置组。
- 新增备选槽位 2 配置组。
- 配置组总数由 6 增至 8，继续使用现有 8 位事务掩码。

当前 NVS 与 BLE 配置服务复用同一桥接编码函数。实施时必须拆分为完整设备表的 NVS wire v2 编解码，以及不超过 48 B 的分组 GATT 编解码；不能通过扩大栈上配置组缓冲绕过 MTU 约束。

原桥接组维持既有单设备字段语义；只操作旧桥接组的客户端不会清空未写入的备选槽位。两个新增组使用独立 UUID，并加入配置服务测试、meta 组掩码和技术文档。

### 6.4 HTTP JSON

schema 14 的配置 JSON 增加固定上限的 `bridge_devices` 数组。每项包含：

- `address`
- `addr_type`
- `name`

全局字段继续表示来源和共享校正。服务端拒绝超过 3 项、重复身份、非法地址和超长名称。现有 2048 B 配置 JSON 缓冲足以承载三设备，但必须增加最坏长度测试，禁止依赖估算。

## 7. 运行时状态机

| 状态 | 实际输出 | 行为 |
|------|----------|------|
| `DISABLED` | 用户选择的模拟输出 | 未配置真实来源、跑步模式或无设备 |
| `FAST_RECOVERY` | 0 W、踏频无效；模拟心率按零负荷或固定配置运行 | 在 60 秒窗口内最多两轮尝试已保存设备 |
| `LIVE_BRIDGE` | 有效真实桥接数据 | 使用当前设备，记录最近成功身份 |
| `FALLBACK_SIMULATION` | 完整模拟功率、踏频和心率 | 等待下次低频恢复 |
| `BACKGROUND_PROBE` | 模拟输出保持连续 | 定向尝试一台设备，不让连接过程打断模拟输出 |
| `PAUSED_FOR_MANUAL` | 模拟输出保持连续 | 用户主动扫描、测试或更换设备 |

### 7.1 冷启动

下游 BLE peripheral 启动完成后，如果持久配置为骑行真实来源且设备表非空：

1. 进入 `FAST_RECOVERY`。
2. 最近成功设备优先。
3. 在 60 秒总窗口内最多遍历两轮。
4. 单次定向连接超时保持 8 秒。
5. 连接成功但 10 秒没有 CPS 通知时，该候选失败。
6. 任一设备连续两份合法 CPS 样本后进入 `LIVE_BRIDGE`。
7. 窗口耗尽后进入 `FALLBACK_SIMULATION`。

### 7.2 异常断连

`LIVE_BRIDGE` 中发生明确断连、GATT 错误或通知超时：

1. 真实功率立即归零，真实踏频立即失效。
2. 进入 `FAST_RECOVERY`，先尝试刚断开的设备，再尝试其他备选。
3. 60 秒内恢复后直接回到 `LIVE_BRIDGE`。
4. 60 秒耗尽后切换到 `FALLBACK_SIMULATION`。

不能保持最后功率，也不能在快速恢复阶段提前混入模拟功率。

### 7.3 模拟降级与低频恢复

`FALLBACK_SIMULATION` 使用当前已保存的模拟参数生成完整输出，但不修改用户的真实来源配置。

- 每 60 秒进入一次 `BACKGROUND_PROBE`。
- 每次只尝试一台设备，并按候选顺序轮转。
- 尝试期间模拟输出继续运行。
- 尝试失败后返回模拟降级，不产生周期性 0 W。
- 任一设备连续两份合法样本后，在主循环下一 tick 原子切到真实桥接。
- 3 台设备均存在时，单台设备最长约 3 分钟再次获得一次低频尝试。

### 7.4 手动操作

用户主动扫描或测试时：

1. 协调层进入 `PAUSED_FOR_MANUAL`。
2. 停止当前上游会话并保持模拟输出。
3. 扫描只由 Portal 明确触发且限时运行。
4. 测试成功不会直接改持久配置。
5. 取消、超时或保存结束后，根据最新配置重新进入快速恢复或禁用状态。

## 8. 功率与输出语义

真实样本处理顺序保持：

1. 校验 CPS 编码和样本年龄。
2. 连续两份合法通知后确认来源有效；0 W 也是合法通知。
3. 原始功率小于等于 0 W 时直接输出 0 W。
4. 仅对正功率执行共享的原值、瓦数或百分比校正。
5. 最终结果夹紧到 0 至 `POWER_MAX`。

设备切换不会改变校正配置。由于用户选择所有设备共用校正，Portal 必须明确提示该配置会应用到全部已保存功率计。

模拟输出与真实输出不做渐变、平均或叠加。切换发生时允许数值跳变，页面必须显示实际来源变化，避免把过渡算法误认为真实测量。

## 9. Portal 交互

### 9.1 设备列表

“来源设备”展示最多 3 行：

- 名称与地址末尾。
- `正在使用`、`最近成功`、`备选`、`连接失败`状态。
- “立即连接”操作。
- “设为首选”操作。
- 删除操作。

列表已满时，新增设备必须先选择替换对象，不能静默覆盖。删除当前设备需要确认；删除最后一台设备会把持久来源切为模拟。

### 9.2 运行状态

实时区域必须同时展示：

- 配置来源：真实功率计或模拟。
- 实际输出：具体真实设备、快速恢复、模拟降级或手动管理。

模拟降级时显示：

- 下一次尝试剩余时间。
- 下一候选设备。
- “立即重试”操作。

运行时自动降级不能把来源选择器改成模拟，也不能伪装成用户已保存的新配置。

### 9.3 校正与模拟参数

- 校正区域显示“适用于全部已保存功率计”。
- 真实来源页面增加紧凑的“降级模拟参数”摘要。
- 用户可以编辑已有模拟目标，但不会因此改变真实来源意图。
- 运行状态轮询不能覆盖正在编辑的草稿。

### 9.4 扫描与替换

新增或更换设备仍使用：

1. 用户主动扫描。
2. 选择 CPS 候选。
3. 短时连接测试。
4. 两份合法样本后允许保存。

扫描前提示将暂时释放当前上游连接，期间继续模拟输出。历史扫描 RSSI 不能作为当前连接信号展示。

## 10. 异常处理

- 自动连接只针对已保存地址，不扫描、不按名称猜测。
- 无效最近成功提示回退首选设备。
- 单设备失败不能清空其他设备。
- NVS 最近成功提示保存失败只影响下次开机排序。
- 自动降级不保存配置、不增加 revision、不设置配置 dirty。
- 自动恢复日志只记录状态切换、候选变化和最终结果，禁止逐 tick 刷屏。
- 协调层不在锁内调用 BLE、NVS、日志、JSON 或 HTTP。
- 手动扫描和自动恢复互斥，退出手动流程后必须恢复自动状态机。

## 11. 测试设计

### 11.1 纯 C 单元测试

新增主备协调测试：

- 最近成功设备优先。
- 最近成功提示失效后回退槽位 0。
- 地址类型和地址共同去重。
- 两轮快速尝试和 60 秒总窗口。
- 三设备全部失败后进入模拟降级。
- 每 60 秒只轮转尝试一台。
- 背景连接期间模拟输出连续。
- 两份合法样本后原子切换真实来源。
- 真实 0 W 可确认来源并保持输出 0 W。
- 手动暂停、取消和恢复。
- `uint32_t` 时间回绕。

扩展桥接领域测试：

- 原值、正负瓦数、正负百分比下 0 W 均输出 0 W。
- 负功率输出 0 W。
- 共享校正在设备切换后保持一致。
- 无效样本不能触发真实来源切换。

### 11.2 会话与配置测试

- 连接失败、无通知、异常断开、旧回调代次和候选切换。
- schema 13 到 14 迁移。
- bridge wire v1 到 v2 迁移。
- 三设备 NVS 与 JSON 往返。
- 非法、重复、超量设备校验。
- 8 个 BLE 配置组全部可编解码且不超过 48 B。
- 旧桥接组写入不清空两个备选槽位。
- 最近成功提示写入失败不影响运行。

### 11.3 Portal 自动化

- 添加、替换、删除和设为首选。
- 列表满额提示。
- 正在使用、最近成功和备选状态。
- 快速恢复与模拟降级文案。
- 下一候选倒计时和立即重试。
- 手动扫描暂停自动恢复。
- 共享校正文案和 0 W 预览。
- 保存失败、结果未知、revision 冲突和草稿保留。
- 与运动模式未保存隐藏实时区的既有方案 B 回归兼容。

### 11.4 工程与真机门禁

自动验证：

- host 全量单测。
- BLE 协议 golden vectors。
- NVS/schema 静态门禁。
- generic-c3 与 m5stamp-c3 双板构建。
- Portal JavaScript、结构、容量和 320/390/1440 渲染门禁。

真机验证：

- 重启后自动连接最近成功设备。
- 异常断线后 60 秒内恢复。
- 主设备缺席时备选接管。
- 全部设备缺席后模拟输出连续。
- 设备重新出现后低频恢复并自动切回。
- 真实 0 W 在三种校正模式下都保持 0 W。
- WiFi、下游 BLE peripheral 和上游功率计共存时空闲堆大于 80 KiB。

多设备真机门禁至少需要两台真实或可控 CPS 夹具。缺少夹具时可以完成自动 harness，但不能宣称多设备实物验收完成。

## 12. 影响范围

预计影响：

- `components/bikepower_domain/`：设备表、协调层、配置校验、编解码和单测。
- `main/ble_power_bridge.c`：暴露单候选终态与切换所需状态。
- `main/app_main.c`：冷启动、主循环动作和实际输出来源选择。
- `main/nvs_store.c`：wire v2 和最近成功运行提示。
- `main/ble_config_service.c`：两个备选配置特征与 8 组事务。
- `main/wifi_portal.c`、`main/web/`：三设备 API 与交互。
- `tests/`、`test/`：状态机、迁移、Portal、协议和真机门禁。
- README、技术参考、BLE 领域规则、CHANGELOG 和 PROGRESS。

本功能必须作为独立桥接批次实施。当前未提交的 Portal 运动模式方案 B 先单独验证和收口，禁止把两组改动混成一个提交。

## 13. 验收标准

满足以下全部条件才视为自动化实现完成：

1. schema 13 和 bridge wire v1 可无损迁移为单设备 v14 配置。
2. 三设备主备协调的所有纯 C 状态机测试通过。
3. 冷启动、快速恢复、模拟降级和低频恢复行为与本设计一致。
4. 任何校正模式下真实 0 W 均输出 0 W。
5. 自动恢复期间不进行后台扫描。
6. BLE 配置组仍不超过 48 B，Portal 配置 JSON 不超过容量。
7. 双板构建、host 全量测试和静态门禁通过。
8. 未完成至少两台 CPS 来源的真机验证时，报告明确标注该人工边界，不发布固件。
