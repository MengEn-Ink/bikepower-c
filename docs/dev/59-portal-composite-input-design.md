# 59 - 组合数值输入与配置页交互优化

用户要求：深浅主题用图标；固定功率与浮动在一行展示，踏频同理；探索更简单的输入方式，并审核整页交互。继续优化现有页面，保留已经确定的顶部个人参数、双主题和骑行强度滑杆。

## 输入方案

采用组合输入：目标值在左，单位紧随其后，右侧单独显示且可编辑 `±浮动值`，例如 `220 W | ±50 W`、`88 rpm | ±8 rpm`。两项都保留真实数字输入和独立的无障碍名称。下方原生滑杆仅调整浮动量，与右侧数字双向同步；手机两组纵向排列，桌面可并列。

| 方案 | 适用性与权衡 |
|---|---|
| 精确数字 + 右侧浮动 + 原生滑杆（采用） | 两项同时可见；键盘精确输入、触屏快速调整；保留熟悉的输入与滑动交互 |
| 数字 + 加减步进按钮 | 适合小步微调，较大改动需反复点击；组合栏会挤占手机空间 |
| 自定义滚轮选择器 | 增加代码与手势处理；纵向选值和页面滚动可能冲突，精确键入不便 |

参考依据（2026-11-09 查阅，设计建议按本项目取舍）：

- [MDN 原生 range](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/range)：滑杆适合近似选值，精确值仍应提供数字输入。
- [IBM Carbon Slider](https://carbondesignsystem.com/components/slider/usage/)：数字输入与滑杆同步是已有组件模式，范围过大不宜只用滑杆。
- [WAI Slider Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/slider/)：方向键/Home/End 是惯例，触屏辅助技术须实测；本轮保留数字输入作为替代。

保留原 `simPower`、`simCadence`、`powerFloat`、`cadenceFloat` 与保存数据映射。功率 0–2000 W、踏频 20–120 rpm、功率浮动 0–100 W、踏频浮动 0–20 rpm，均为整数。数字非法时保留草稿并显示明确范围，禁止保存；不要让滑杆静默改写非法值。保存等待及配网结束时暂停编辑。机器人隐藏固定模式浮动量，切回仍保留原值。

## 主题图标

使用统一笔画的内联月亮/太阳 SVG，表示点击后切换的目标主题；44 px 点击区域。保留动态 `aria-label`、悬停 `title`、键盘焦点与原持久化逻辑，不引入图标库。

## 整页审查与本轮修复

基于当前生产页的离线 Chromium 复核：

1. 非法功率 `-1`：没有 `aria-invalid`，底部只提示输入范围/配速/名称，缺少字段定位。本轮对新组合输入提供字段旁的具体校验提示。
2. 扫描弹窗 Tab：焦点列表包含隐藏的替换下拉框与确认按钮，最后一台候选后 Tab 离开弹窗。本轮只将可见、可用控件纳入焦点循环。
3. 跑步配速清空：速度说明出现 `NaN km/h`。本轮无效时改为可读的输入提示。
4. 隐藏非法草稿：跑步配速清空后切回骑行仍禁止保存。整份配置校验有其必要性；后续建议增加“一键定位错误”并自动展开对应模式，避免直接放宽校验。
5. 草稿恢复：没有整页撤销入口或可靠的离页保护。后续建议提供“恢复已应用配置”，明确草稿与已应用值；离页提示只能补充，不能保证手机后台退出时生效。

后两项作为后续建议，不更改当前配置事务或自动持久化策略。审查为交互与实现检查，不宣称完成屏幕阅读器/实体设备认证。
