# Pages 串口刷写稳定性排查与加固

## 结论和证据边界

本轮处理的是网页刷写工作流，不是修改固件。用户报告“选择串口后无反应”和刷新异常；内置浏览器实际打开Pages，起初704px宽被分流至移动只读首页，窗口扩至桌面宽度后刷写按钮可触发串口选择，取消选择有明确提示。串口选择接管超时，未取得当前Mac开发板选中后完整链路证据，不能宣称已定位该板硬件根因或实物刷写成功。

源码与受控回归证实以下缺口：

- 页面初始化等待所有资源load，慢图片/字体会推迟路由与按钮接线；改为DOMContentLoaded，并保持defer模块顺序。
- 选串口后下载和校验缺少阶段/字节进度，用户容易以为无响应；新增清单、下载、校验、组件、打开串口、安装、清理状态。
- 刷写组件依赖外部CDN，选中后才动态加载且可能失败；完整锁定版本改为本站同源按需加载，取消重复的上游按钮选择器。
- 串口open/close无提示期限；15秒后明确超时并继续禁止重复操作，等待原Promise真正settle后再清理；迟到open不能创建安装弹窗。
- 页面刷新后不能区分上次会话是否中断；sessionStorage只存版本、阶段、开始时间，不保存串口身份、设备配置或密钥。刷新后明确“不能确认成功”，绝不自动续写。
- 小于900px的移动分流会隐藏桌面流程；桌面平台且支持Web Serial时提供主动打开的紧凑刷写入口，704px入口及无横向溢出回归。活动会话保持刷写页及实际弹窗可见，闲置手机仍为精简只读首页，设备状态原移动入口保持。

## 成熟方案对照与选择

参考固件羊：https://easyhey.com/?firmware=MOD220 。借鉴分阶段反馈和连接引导，不复制其私有代码，不把网页宣称的成功率当本项目实测。本轮没有在参考网站点击烧录，不把MOD220固件用于BikePower。

ESP Web Tools官方：https://esphome.github.io/esp-web-tools/ 。官方支持本地托管脚本、manifest和Blob清单；本项目继续使用锁定10.4.0内核、芯片检测及确认界面，保存完整dist/web快照和Apache-2.0许可证。不改上游私有状态，不以INSTALL宿主、写入100%或弹窗关闭判定成功。

Espressif esptool-js：https://espressif.github.io/esptool-js/docs/ 。更底层方案可提供自定义日志/检测/传输，但直接替换意味着重做芯片复位、读写锁、校验、失败收尾等。本次先修现有集成，不同时增加第二个串口所有者或WebUSB回退。官方示例说明连接检测会复位设备，且全量BIN会擦写覆盖范围内的NVS；不能把普通“连接测试”当无副作用读取。

## 具体实现

- flash-session.js：下载字节反馈、安全准备取消、锁定同源加载、open/close迟到操作保护、刷新中断记录、保持SHA256/大小/芯片/0x0清单校验。
- ble-monitor.html：ARIA状态区与“取消准备（尚未写入）”按钮、向导同步真实反馈、活动窄窗显示、DOMContentLoaded启动；安装仍需上游显式确认。
- flash-dialog.js：纠正“未勾整片擦除就能保留”的误导，明确本全量固件覆盖配置/绑定；终态关闭和失败恢复仍走真实组件接口。
- vendor/esp-web-tools-10.4.0：上游浏览器模块逐字节保存，同源加载；锁版本、许可证和模块依赖闭包单测。
- 原有真实组件浏览器回归新增下载中刷新记录、窄窗实际ew-dialog可见、无重复选择器与无自动重刷；没有放宽原固件校验和失败断言。

## 用户如何排查

1. 未出现串口列表：使用桌面且支持Web Serial的安全浏览器；先检查页面明确提示，不反复刷新和开多个标签页。
2. 选中后显示下载：观察字节数；停滞30秒会终止实际请求。尚未打开串口阶段可点取消准备，等待收尾后重新选择。
3. 打开串口超时或不可读写：关闭确实占用该设备的串口终端，检查数据线；底层未结束前页面不允许第二次操作。
4. 安装弹窗未显示：活动会话窄窗不再隐藏弹窗；组件加载失败会明确提示。此时不自动执行安装。
5. 芯片握手失败：保留日志，核对正确开发板串口和数据线。必要时用户按BOOT并点EN/RST进下载模式，再关闭失败弹窗主动重试；不自动提高波特率或擦除。
6. 刷新/关闭过页面：上次结果未知，不据此判断成功或失败。先检查板状态再主动重新选择，绝不自动续写半包。
7. 写入100%：仍等待校验/重启终态和串口释放；成功以后再进行独立BLE连接验证。

## 风险和未实现能力

- 没有烧录/整片擦除/清配对/改MAC/改NVS，也没有发布新固件或修改合并镜像写入范围。
- Web Serial的open/close没有标准取消API；15秒是提示和隔离期限，不是假称底层已经停止。底层永不返回时仍须关闭页面排障，不允许新会话抢占。
- 原刷写引擎错误/成功仍由真实渲染终态识别，不能从页面截图反推板端校验；本次串口替身回归不代表物理烧录耐久。
- 未新增稀疏保留式升级、断点续写、设备自动重配对或跨版本回滚迁移。全量BIN覆盖NVS的风险仍存在。
- 内置浏览器本轮JS诊断接口不可用，采用可见DOM/请求/取消反馈；未读取用户浏览器资料或隐私配置。
