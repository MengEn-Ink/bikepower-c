# 手机实体演示可行性与实施方案

2026-11-06 调研与本地渲染核对。推荐采用**真实配置页面 + CSS 手机实体外壳 + 操作时间轴**，导出视频复用现有 Playwright / FFmpeg 流程。

## 呈现范围

演示明确分为两个入口：

| 入口 | 主体 | 展示内容 |
|---|---|---|
| 设备操作 | 设备实体 | 操作键按住、松开、再次确认、调节目标、指示灯 |
| 手机操作 | 完整手机实体 | 真实页面的点击、滚动、编辑、保存、切换模式、选择功率计 |

用户截图提供的是手机外观与屏幕呈现参考，画面内为“此里”活动页。借鉴黑色机身、圆角屏幕、状态栏和整体比例；BikePower 屏幕使用自己的真实页面、字号、控件、文案和弹窗。

## 成熟方案比较

比较依据：真实界面对齐、可交互性、页面更新维护、当前项目接入成本。以下成本为工程判断，不是实测工时。

| 方案 | 真实界面对齐 | 可交互性 | 页面更新维护 | 接入成本与结论 |
|---|---|---|---|---|
| CSS 手机框 + 真实网页嵌入 | 复用生产 HTML/CSS/JS | 支持真实控件与演示时间轴 | 构建时同步页面来源 | 推荐。当前项目可继续用原生网页；iframe 是成熟浏览器能力，[来源 1](#source-1) |
| 手机框 + 实际页面录制 | 对齐录制时的页面 | 播放、暂停、逐步片段，不能自由编辑 | 页面变化后重录 | 适合系统 WiFi、浏览器弹窗和第三方 App；网页部分可用 Playwright 采集，[来源 2](#source-2) |
| Remotion 视频合成 | 取决于是否使用真实页面素材 | 支持播放器与参数化时间轴 | 维护 React 合成项目及素材 | 能做，但当前不是必要依赖；适合后续批量制作演示视频，[来源 3](#source-3) |

Devices.css 提供纯 CSS 手机和平板外观，仓库许可为 MIT；可作为成熟结构参考。[来源 4](#source-4) 核对时仓库未归档，但最后推送为 2023-01-10，不能据此宣称持续活跃维护。建议按用户截图制作中性手机框，避免直接引入全部历史机型样式。

3D 模型不作为首选：本次成功标准是看清操作位置和实际反馈；机身转动或屏幕透视会增加对齐与阅读成本。这是本项目的设计判断。

## 本地可行性证据

本次通过已有 `tests/mock_server.py` 提供**生产使用的** `main/web/index.html`、`app.css`、`app.js`，将实际页面嵌入手机外壳后由 Chromium 渲染。

- 实测内页宽度为 390 CSS px，无横向溢出。
- 页面标题为“BikePower · 设备配置”；骑行、跑步、模拟输出、真实功率计、选择功率计等控件来自原页面。
- 底部“关闭 WiFi”“保存并应用”保持原页面固定操作栏。
- 本次只验证页面渲染与嵌入可行性，数据来自本地 mock，未连接或修改实体设备。
- 本地 Chromium 可用，WebKit 二进制未安装。本图不是 iOS 真机或 Safari 验收结果。

## 推荐实现

1. **共用真实页面来源。** 生成演示页面时内联生产 HTML/CSS/JS。演示接口先于原脚本初始化，在演示内部响应 `/api/state`、配置保存、扫描等请求；GitHub Pages 不依赖 Python 服务，也不访问实际设备地址。显示“模拟演示”，成功与失败沿用真实页面反馈。
2. **手机框只负责外观。** 状态栏、机身、侧键和底部手势条独立于屏幕。手机内部使用固定逻辑视口，整个机身等比缩放；不能缩窄内页后导致按钮和排版重新排列。具体逻辑视口按选定手机与实际浏览器校准。
3. **动作对齐实际控件。** 点击提示跟随真实按钮边界；滚动、展开或缩放后重新定位。编辑触发实际输入事件，保存等待页面反馈，再进入下一步，避免用预定时间冒充成功。
4. **只保留一个活动手机页面。** 切换教程时复用它或销毁上一实例；暂停、折叠、离屏时停止时间轴，避免同时运行大量 iframe。[来源 1](#source-1)
5. **离线隔离。** 可使用内联 `srcdoc` 和限制脚本权限的 iframe；当前真实页面通过脚本提交配置，需核对嵌入模式下的能力。跨框消息校验窗口来源与消息类型。不能把同源 `allow-scripts + allow-same-origin` 当成可靠隔离边界。[来源 1](#source-1)
6. **系统操作采用实录。** 手机 WiFi 设置、自动配置窗口、Safari 工具栏及第三方 App 不属于 BikePower 网页。用对应系统、版本的真实截图或录像；演示不得声称网页可以操纵手机系统设置。
7. **同源导出。** 手机实体与页面动作使用同一个演示场景；继续用现有录制与编码工具导出 MP4 / GIF，暂不引入 Remotion。

先实现“编辑目标 → 保存成功 → 关闭 WiFi”完整手机场景，再扩展骑行、跑步和真实功率计。设备操作继续使用按键与灯光时间轴。

## 对齐验收

- 同一版本、主题、逻辑视口、字体和配置状态下，比对原页面与手机框内页；截图比较时排除倒计时与实时动态数字。
- 按钮标签、顺序、固定栏、展开状态、确认弹窗与保存失败恢复必须一致。
- 使用 Chromium 和 WebKit 的移动设备参数验证触屏与布局；浏览器模拟支持视口、屏幕、触摸和设备像素比，但不是实体 iPhone 系统 UI。[来源 2](#source-2)
- 手机系统的弹窗、软键盘、安全区域和动态浏览器栏最后仍需实际手机核对。

## 已批准实施：2026-11-06

- 首页分为“设备操作”和“手机操作”。设备继续呈现实体按钮、回滚、确认与大范围灯光；手机展示完整机身、状态栏、摄像头、侧键和手势条，内页固定 390 × 782 CSS px，整体等比缩放。
- `build_phone_demo.py` 从生产 `main/web/index.html/app.css/app.js` 生成屏幕来源，初始响应复用现有 mock fixture。站点构建自动重新生成；离线手册与独立 HTML 内联同一来源。`--check` 可检查生产来源漂移。
- `phone-demo-adapter.js` 只进入演示屏幕，用内存响应状态、扫描、测试、配置事务和关闭请求。原页面实际显示保存错误、保留草稿、重试成功与关闭确认；父页面不制造成功状态。
- 屏幕采用 `sandbox="allow-scripts"`，不授予同源权限；CSP 禁止网络与表单提交，演示 fetch 拒绝非演示接口，品牌链接只回到屏幕顶部。消息核对父窗口 / iframe 窗口与随机会话 token。
- 动作通过真实输入事件、按钮点击和原页面返回结果推进；点击标记使用实际 DOM 边界，滚动重新定位。保存完成后还等待页面轮询更新输出。
- 页面只保留一个实际 iframe；其他教程按需激活。暂停、切换、折叠、离屏与页面隐藏停止时间轴和屏幕轮询；直接在手机屏幕操作时恢复轮询。替换教程清理对应监听和观察器。
- 手机主场景覆盖修改/失败/重试/关闭、扫描/选择测试/校正/0W、跑步、骑行与名称。体重、步进、版本、功率计接入和退出等补充教程复用同一真实屏幕。
- 原页面没有跑步暂停控制按钮，因此手机配置教程只演示实际支持的配速与运动类型切换；运行/暂停由运动 App 控制，不在配置页虚构按钮。手机系统及 App 步骤明确为示意，尚未获得对应版本的实录素材。

产物位于 [操作演示目录](../../design-demos/bikepower-ui/operation-demos/)；独立交互 HTML 为同源快照，手机 MP4/GIF 从其真实操作流程录制。浏览器测试与实物边界见 [实施记录](39-pages-operation-demos.md)。
