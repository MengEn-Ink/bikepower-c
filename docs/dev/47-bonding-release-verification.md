# v4.3.3 持久绑定与正式发行核验

本轮仅发布通用 ESP32-C3；鬥骑新候选复测按用户要求跳过。当前候选自动验证结果告知用户后，用户明确要求继续发布。最终提交镜像、严格 P0、发行附件及远端下载结果以随固件 `test-report.md` 为准。

## 问题与修复

受控 pair-only 测试不写配置、不改 GATT。旧无绑定候选首次加密成功，第二次建链后恢复加密返回 HCI 0x06（缺密钥）并由 Windows 拆链。提供程序裁剪了 Start Encryption 与配对参数，不能据此推断 EDIV/Rand 或密钥值。

改为标准 NimBLE 持久绑定，容量4、SC Just Works、ENC/ID分发；本机仍 public，FTMS WRITE_ENC 不降低，用户配置 namespace/schema 和分区不变。项目启动核验 NVS 记录格式与恢复内容，同身份更新补落盘回读，存储失败拒绝后续密钥恢复及训练控制。容量满拒绝新增，不自动删除旧客户端。host 同步时发送全范围 Service Changed，供服务表变更后重新发现。

## 保留的失败与纠正

- 第一持久绑定候选已绑定GATT重建后WinRT服务发现失败，原失败保留；不能用当时清测试配对的恢复当作修复PASS。
- 配置E2E倍率上界1500过时，生产合法范围至3000，测试增加500/1500/1877/3000边界，不改生产协议。
- 首耐久脚本漏正常pair而遭ATT0x05，恢复后补配对复跑；不降低认证。
- 一次隔离源复制保留旧mtime，使Ninja复用私有清理object，hash核查发现；强制重编译并精确回刷正确生产。错误日志保留，不作为生产刷写成功证据。
- 本轮只定向清理经备份解析确认的新增测试peer，保留本机IRK和用户配置；私有Flash、HCI原件和临时清理镜像不提交、不分发。
- 首full回归环境遗漏子进程解释器和cJSON来源导致5失败；修正进程环境后原断言43通过。

## 使用限制与未执行项

系统单侧“忘记设备”后板仍保留旧绑定，会拒绝覆盖；当前没有用户清绑定入口，需要定向维护，不建议整片擦除。真实多客户端容量满和存储写失败未做实物注入，仅host专项。实体按钮/LED、手机热点、跑步App、M5Stamp C3实物及新鬥骑复测未执行，不能沿用旧镜像验收。

发行仍必须以最终提交干净构建、应用回读、当前镜像五项P0、合并单bin及8个单板标准附件、严格SHA/manifest/ZIP校验完成后才能执行tag和Release。Pages跟随原GitHub Actions链路，下载后重新计算摘要。
