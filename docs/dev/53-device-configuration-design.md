# 53 - 设备配置页视觉与操作优化设计

状态：用户已批准并完成本地实施；正式配置页、派生手机演示与离线手册已同步。验证结果见文末。

## 目标与现状

使用本项目安装的 `frontend-design` 技能，围绕“查看实际输出 → 修改设置 → 保存并确认”优化设备配置页。

当前生产页面为 `main/web/index.html`、`app.css`、`app.js`。现状浏览器回归已通过 320、390、1440 像素三种宽度的保存失败重试、功率桥接与跑步切换流程。

从生产页面截图与源码确认：

- 手机端大多数标签与说明为 12 像素，设置区层级紧凑。
- 桌面左侧输出区域随右侧长表单拉伸，留下大面积空白。
- 桌面设备名称与固件文字缺少独立行布局。
- 广播选项的第四项单独落在第二行，与前三项的语义差异不够直观。
- 页面只有浅色变量，顶栏、操作栏与部分状态色使用固定颜色。
- 草稿与实际输出已分离，保存失败保留草稿；这一行为必须继续保持。

现状截图：[手机](../images/configuration-before-mobile.png)、[桌面](../images/configuration-before-desktop.png)。

## 方案比较

| 方案 | 内容 | 优点 | 代价 |
|---|---|---|---|
| A：训练设备工作台，推荐 | 保留现有编辑流程，优化输出摘要、表单节奏、广播分组与状态反馈，补齐系统深色适配 | 兼顾熟悉感、可读性与维护成本 | 需要复核所有视图和派生手机演示 |
| B：纯样式微调 | 只调字号、间距与颜色 | 变更范围最小 | 桌面空白、长表单结构与广播选项层级改善有限 |
| C：逐步配置向导 | 按来源、目标、广播、保存拆成步骤 | 首次配置容易理解 | 熟练用户操作变慢，新增流程状态较多 |

推荐 A。配网页是短时间设置工具，用户需要迅速找到目标值，也需要核对当前真正输出。保持直接编辑，比增加向导更适合这个任务。

## 视觉方向

采用克制的训练设备界面：中性底色、明确的数字层级、稳定的表单对齐。金色集中用于品牌标记和可执行的保存按钮，状态信息使用文字与图标共同表达。

### 配色

|---|---|---|
| 页面底色 | `#F3F4F6` | 页面外围 |

| 主文字 | `#17191D` | 标题、数值、控件文字 |
| 次文字 | `#59616D` | 标签说明、单位 |
| 分隔线 | `#D8DCE2` | 区域和控件边界 |
| 保存金色 | `#F5C451` | 主操作和品牌 |

深色基础六色：

| 名称 | 色值 | 用途 |
|---|---|---|
| 页面底色 | `#14161A` | 页面外围 |
| 工作表面 | `#202329` | 编辑区 |
| 主文字 | `#F4F5F7` | 标题、数值、控件文字 |

成功、警告、失败使用各自可读的语义色与背景组合，实际对比度通过浏览器检查。首次跟随系统主题，顶栏“深色 / 浅色”按钮切换后保存到浏览器；已保存选择优先。主题只属于页面显示，不新增设备配置字段。

### 字体与尺寸

- 使用本机中文无衬线字体栈，避免热点环境依赖网络字体。
- 表单标签 14 像素，主要说明 14–15 像素，输入文字至少 16 像素。
- 区域标题 16–18 像素；实际输出数字桌面 60–64 像素，手机 36–40 像素。
- 数字使用等宽数字特性，刷新时避免宽度跳动。
- 主控件高度 48 像素，其他交互目标至少 44 像素。
- 内容统一左对齐，数值与单位基线对齐；不为装饰增加编号和标签。
- 节间距采用 16、24 像素，区分输入组与独立设置区；使用少量结构性分隔线。

## 布局与操作

### 桌面

工作区最大宽度约 1120 像素。左侧约 340 像素展示实际输出，右侧用于编辑。两个区域各自有明确边界，不让输出摘要被长表单拉成空白大面板。普通桌面滚动时左侧摘要保持可见；模式尚未应用时沿用现有单列提示行为。

```text
品牌          设备名称 / 固件          配网剩余时间、续期

                      骑行 / 跑步

当前实际输出          输出设置
220 W                 输出来源：模拟 / 功率计
踏频、心率            固定功率 / 配速机器人
来源与连接状态        目标功率、踏频
运行详情              浮动、广播、心率、设备设置

保存状态与说明                     关闭 WiFi   保存并应用
```

### 手机

先显示紧凑的真实输出摘要，随后进入设置。390 × 844 像素视口下，默认骑行状态应能看见目标功率输入框，不被底部保存栏遮挡。320 像素宽度下字段与单位完整显示，无横向滚动。

```text
品牌                 剩余时间、续期
             骑行 / 跑步
当前输出     220 W / 88 rpm / 145 bpm
来源、连接状态 / 运行详情

输出来源
模式
目标功率            模拟踏频
浮动设置
广播、心率、设备设置

保存状态
关闭 WiFi           保存并应用
```

保留输入位置和现有字段顺序，通过尺寸、对齐与分组改善查找速度。暂不新增步骤向导，也不把浮动字段移入新的隐藏层级。

### 表单分组

- 输出来源和模拟模式保持当前渐进披露行为。
- 目标值与浮动值通过组内间距形成两层，不使用完全一致的视觉权重。
- 功率、踏频、心率并列；“踏频随功率”单独作为兼容设置行，避免看起来像第四种运动数据。
- 心率模式、联动参数和固定心率参数继续按当前选择显示。
- 设备名称、按钮与固件信息保留折叠入口，改善设备名称与固件信息的排版。
- 主备功率计、扫描窗口、校正预览及跑步视图沿用同一视觉规则。

### 保存与状态

保留固定保存入口，给所有状态足够的文字宽度：

| 状态 | 页面表现 |
|---|---|
| 尚未修改 | 清晰显示已应用；保存按钮禁用但文字可读 |
| 有修改 | 显示待保存提示，实际输出继续显示已应用值 |
| 正在保存 | 显示确认进度，防止重复提交 |
| 保存成功 | 状态栏持续显示已应用，短提示辅助确认 |
| 保存失败 | 错误持续留在状态栏，保留草稿并允许重试 |
| 运动类型待切换 | 显示当前与待应用类型的区别及连接影响 |
| 即将关闭配网 | 继续使用现有警告、续期及关闭确认 |

错误文字使用现有接口产生的真实信息；不增加模拟成功、不改变事务确认条件。

## 实现边界与影响

主要修改范围是生产前端三件套。保持元素 ID、字段名称、范围、默认值及 API 请求契约稳定。

同步检查：

- `tools/web/phone-portal-source.js` 由生产页面生成，需要随生产页更新。
- 离线手机手册和独立演示包含生产页快照，需要重新生成并验证对齐。
- 现有页面渲染门禁和手机演示回归需要覆盖新的布局。
- 更新与页面实际改动相关的用户说明、技术文档、CHANGELOG、PROGRESS。

页面仍采用编译时内联方式，不引入网络字体、UI 框架或外部资源加载。此轮不修改配置 schema、BLE 协议、功率算法、WiFi 射频流程或固件版本号。

已有 BLE 规则修改及 AgentBuddy 安装文件属于工作区基线，不纳入本轮页面改动。提交、推送、烧录和正式发版另按用户授权执行。

## 验收

1. 320、390、768、1440 像素，浅色与深色都无横向溢出；所有表单文字、占位、禁用态与状态提示可读。
2. 普通文字对比度至少 4.5:1；大字至少 3:1，必要控件边界与焦点至少 3:1。
3. 默认 390 × 844 像素界面能看见目标功率输入框，滚动后的最后一个控件可完整露出底部操作栏。
4. 修改目标不提前改变实际输出；成功确认后才更新；失败保留草稿并可重试。
5. 桥接扫描、三设备主备、共享校正、停踩 0 W、跑步切换继续通过现有浏览器回归。
6. 使用键盘能完成操作，焦点清晰；减少动画偏好关闭非必要过渡。
7. 生产门户、嵌入手机演示和离线手册保持一致的 390 像素布局与控件位置。
8. 运行门户 JS/结构检查、浏览器专项与手机对齐验收；构建内联产物并检查资源体积。

现状验证只代表优化前的基线。优化后的结果需在实施完成后另行记录，浏览器验证不替代真机验收。

## 本地实施与验证（2026-11-09）

- 正式页面共用布局：桌面独立 340 像素摘要，手机压缩输出区，增大标签与输入，兼容广播单独成行，设备名称与固件分行。
- 主题键为 `bikepower.portal.theme.v1`，属于当前浏览器与站点。首次跟随系统；手动选择后优先，刷新保持。存储被禁用时当前页仍可切换；主题按钮不会产生配置修改、保存或续期请求。
- 320、390、768、1440 像素双主题布局、文字对比度、390 首屏目标输入、键盘与系统主题变化回归通过；普通文字至少 4.5:1，大字至少 3:1。
- 三宽浅色与深色保存失败重试、三功率计主备、共享校正、降级恢复、停踩 0 W、跑步切换通过。手机离线演示与同视口生产页面控件及截图完全一致，触屏保存通过。
- 修正内联 CSS 压缩器：只重命名已声明的自定义变量，单次替换避免名称冲突；保留后代伪类前的空格。原压缩器会错误改写 `status-chip--ok` 等类名；浏览器断言已覆盖状态颜色与分行。
- HTML/CSS/JS 内联总量为 96,925 字节，比原版 94,528 字节增加 2,397 字节（约 2.34 KiB），仍满足各部分与总量预算：HTML 18,973、CSS 24,542、JS 53,411 字节。页面仍存放在 Flash，由 HTTP 直接发送；没有新增设备配置字段或常驻堆缓冲。未做真机堆峰值测量。
- [可交互离线配置页](../../design-demos/bikepower-ui/configuration-preview/configuration.html) 使用生产代码和隔离模拟接口，所有保存只作用于演示数据；旧静态设计预览继续作为设计参考。

页面功能已提交并推送，提交 `ddd71b8`。用户追加授权部署正式 GitHub Pages，部署身份以对应 CI/Pages 的最终 SHA 为准。未烧录或发布新固件；浏览器与内联产物检查不代表新版固件已安装到设备。
