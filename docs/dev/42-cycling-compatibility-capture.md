# 骑行端适配差异采集与 Pages 简化

## 目标与范围

后续用户已批准将全站版式、骑行适配采集、移动精简与WiFi配网引导提交到main并部署。本记录中的“未提交/未部署”均为此前本地实施阶段状态；当前发布以对应新提交的CI及Pages工作流为准，不改变固件发布和烧录范围。

用户要求设备比对聚焦骑行 App / 码表适配：采集第三方正常设备与 BikePower 开发板的蓝牙信息，找出差异，分析需要补齐的功能。不是以身份复制作为主流程，不声称复制名称能解决 GATT/协议适配。

移动端删除独立 FAQ/注意事项文字列表，遇到问题入口指向现有排查演示；保留教学中的操作提示，不删除实际配网页。仅修改 Pages、测试和文档，未修改固件、BLE 协议、设备热点配网页、NVS 或发布流程；未提交、推送、部署、烧录。

## 操作流程

1. 点“连接并采集第三方设备”，选一台正常工作的功率计、心率带或骑行台。
2. 点“连接并采集开发板”，采集当前开发板固件提供的能力。
3. 两侧信息分别标识保存；默认逐台连接，采集后释放连接。断开和刷新后仍可比对。可分别导出 JSON，也可先后导入两侧文件。
4. 点“找出差异并分析”，以第三方设备 / 开发板 / 分析与补齐方向的形式列出差异。
5. 修改固件并重新采集，再释放网页连接，到骑行端复测。页面不自动补写固件或执行目标软件的握手。

骑行端名称、版本、系统、角色和失败阶段为可选补充，不阻塞初次采集。第三方正常与否需要用户在目标骑行端确认。旧的名称/DIS模板工具保留在折叠区，不作为功能补齐主入口。

## 双连接与数据边界

- 页面提供“尝试同时连接两台”，两台是不同的 BLE 外设，并不是让同一开发板同时连接网页和骑行 App。
- 实际同时连接成功取决于主机蓝牙适配器、系统/浏览器和设备。当前未实测两台物理设备，因此不能承诺当前电脑一定双连；UI 只在两侧连接对象都实际报告 connected 时显示两台当前连接。
- 默认逐台采集不依赖双连能力；第二台失败、用户取消、设备断开、采集超时不覆盖原快照。单次操作6秒超时，采集总计90秒限时；保留代次与连接归属，旧请求不得清理新连接。
- 采集先由用户打开选择器授权，不自动扫描。新只读入口允许选择任意设备；标准服务列表和手填私有服务 UUID 明确授权。只能读取授权范围内 GATT，不能还原完整广播包、MAC、目标端私有握手或加密空中行为。
- 读取96个可读特征、订阅最多24个通知/指示特征，通知窗口10秒、最多120条原始样本。启用通知会按BLE协议订阅CCCD，但不写业务参数或发控制点指令。上限外读取为skipped，无样本和读取失败不当成不支持。
- 两份快照保存在当前浏览器、当前源下（`bikepower.compatibility.capture.v1`），不上传服务器；file/localhost/正式站点各自存储互不共享。总报告不超过1MiB，存储失败明确提示导出备份。

## 差异内容

- 双向服务与特征差异，不只遍历参考设备。
- Read / Notify / Write / Indicate 等属性。
- CPS / CSC / RSC / FTMS 能力位、只读范围与身份读取值。
- 通知帧长度、flags结构和间隔中位；实时功率数值变化不是应机械复制的能力差异。
- 标准问题、候选原因、采集未知分开；未授权/枚举失败不能判定缺失，第三方设备也接受标准校验。
- 结果保留服务UUID、原始数据、读取状态、采集时间和同一场景下的实测记录；单侧替换使旧人工记录失效。

- `tools/web/operation-demos.js`：比对教学从身份复制改为采集、分析与复测。
- `docs/user/pages-mobile-guide.html`：由既有生成器同步移动端。
- `tests/test_pages_capture_browser.cjs`：只替换外部BLE传输、加速采样等待的实际页面流程；不注入业务模型结果。
- `tests/test_ble_compatibility.cjs`：单侧报告、稳定标识、双向差异与未知权限新增两项。
- `tests/test_ble_compatibility_browser.cjs`：原有注入防护、连接交接测试适配折叠入口。
