# Pages 全站布局与排版更新

## 2026-11-08 蓝牙点击与刷机流程修复

### 已确认原因与修复

原生 Windows Chrome 实际访问在线 `#/monitor` 后点击「扫描并连接设备」，未出现选择器，仅折叠事件日志增加“目标端实测期间网页连接已暂停”。监控页当时保留了跨刷新实测暂停标记，这属于防止网页抢占其他 App 的保护，不是蓝牙 API 不可用。旧界面没有就近恢复入口，容易被误认为按钮失效。

- 监控页新增可见暂停说明与「结束实测，恢复网页连接」，显式恢复后仍需用户再次点击选择设备；跨标签暂停与刷新保留规则不变。
- 选择器等待、取消、权限拒绝、连接失败及无授权设备均在当前页直接反馈；重复点击不产生重复选择器。原生 Chrome 在本地候选页实际打开系统选择器并发现 BikePower，随后取消，没有新增授权/绑定或写入配置。
- `tools/web/flash-dialog.js` 为锁定 ESP Web Tools 10.4.0 的独立中文 DOM 适配器，仅修改可见文案，不访问私有安装状态或修改第三方依赖。串口系统窗口保留浏览器语言；网页内确认、擦除风险、进度、常见失败及完成使用中文。
- 原流程把任何 `closed` 当成刷写成功；现仅可见组件成功终态后2秒自动关闭，调用真实 `ew-dialog.close()` 走上游关闭流程；串口、Blob及Web Lock释放成功后才显示完成引导。未知关闭、失败、写入100%和收尾中不算成功。失败提供主动「关闭并排障」，不自动关闭正在写入的弹窗、不自动重刷；清理失败继续禁止重试。
