# 核心设备门户全量重写设计

日期：2026-11-04

状态：用户已确认第二版交互并授权实施与功能测试，实施中。

关联设计：[真实功率桥接与网页交互设计](14-real-power-bridge-web-design.md)

## 1. 目标

把 ESP32-C3 内置网页从“完整设置中心”重写为轻量现场控制台，首屏直接完成当前运动输出配置和真实功率桥接操作。

本次设计同时满足：

- 设备门户仅提供明主题，不包含暗主题代码。
- 构建后内联 HTML 硬门禁不超过 110 KiB，工程目标不超过 90 KiB。
- 删除旧设备信息模板库及其固件后端。
- LED 配置不再出现在设备门户，由 GitHub Pages 工具台通过 BLE 配置事务管理。
- 保留骑行机器人档和跑步配速档；“删除模板”仅指旧设备信息模板。
- 真实功率计桥接是骑行页面的一级核心来源，不作为后续附加页面。
- 默认来源保持旧版模拟输出；桥接能力只在用户主动选择后渐进披露。
- 保留设备名、按钮调功步进和完整固件详情。
- 体重、FTP、阈值心率不再形成独立资料页，只在相关算法场景中就地出现。

## 2. 非目标

本轮不实现：

- 暗主题、主题切换和跟随系统主题。
- 外部心率带、独立踏频计或多个上游功率计。
- 开机后台扫描、开机自动连接真实功率计。
- 骑行台阻力控制或上游 FTMS 控制透传。
- 断线后自动切回模拟功率或保持最后有效功率。
- 在设备端继续保存外部设备信息模板列表。
- 在设备门户复制 Pages 的刷写、导入导出和完整诊断能力。

## 3. 术语

- **设备模板库**：旧门户维护多个外部设备身份模板的列表及持久化。本轮删除模板库；桥接已选功率计的单次身份复制保留，不创建模板。
- **配速档**：骑行机器人和跑步预设。它们属于核心输出模式，继续保留。
- **设备门户**：ESP32-C3 SoftAP 提供的 Captive Portal。
- **Pages 工具台**：`tools/web/ble-monitor.html` 对应的 GitHub Pages 页面，通过 Web Bluetooth/Serial 管理设备。
- **已应用配置**：固件已经校验、保存并用于输出的配置。
- **草稿**：浏览器内尚未保存的编辑值。
- **运行状态**：连接、遥测、数据年龄、重连和订阅等非持久状态。

## 4. 职责边界

### 4.1 设备门户

设备门户只承担现场高频操作：

- 骑行/跑步切换。
- 广播数据项选择。
- 骑行模拟输出与真实功率计桥接切换。
- 骑行固定功率、机器人档、自定义档和相关浮动参数。
- 跑步固定配速、配速档、自定义档、步频和相关浮动参数。
- 固定/联动模拟心率。
- 上游功率计扫描、测试、启动、停止、更换和校正。
- 与当前算法直接相关的体重、FTP 和阈值心率。
- 设备名、按钮调功步进和固件详情。
- 保存、应用、续期和关闭 WiFi。

### 4.2 Pages 工具台

Pages 继续承担低频高级操作：

- 完整 NVS 配置读取、校验、事务保存和 JSON 导出。
- LED 静默模式、场景灯效和颜色。
- Web Serial 刷写、固件管理和诊断。
- 浏览器侧扫描外部设备并写入 DIS 身份覆盖。

Pages 不依赖旧固件设备模板库。浏览器可以直接读取外部设备，再通过现有 DIS profile 配置特征写入身份覆盖。

### 4.3 固件模块

- `wifi_portal`：静态页面、紧凑状态接口、配置提交和桥接命令分发。
- `ble_scanner`：仅发现符合条件的 CPS 功率计，返回有界候选列表。
- 新桥接会话模块：测试、连接、订阅、数据过期、停止和限时重连。
- 新纯 C 输入编解码模块：CPS Measurement 解析、曲柄踏频计算和异常样本拒绝。
- 领域层：来源仲裁、固定/比例校正、0W 保护和统一输出快照。
- `ble_bikepower`：只消费统一快照并按有效字段发送 CPS/CSC/HRS/FTMS。

桥接模块不得直接保存网页草稿，HTTP 处理函数不得持有长期 BLE 会话对象。

## 5. 页面信息架构

新门户是单页现场控制台，不保留旧 hash 路由、底部多页导航和“设置中心”。

页面自上而下为：

1. 状态栏。
2. 骑行/跑步切换。
3. 当前已应用输出。
4. 当前运动的来源和参数。
5. 广播数据项。
6. 当前算法需要的上下文参数。
7. 设备折叠面板。
8. 底部保存与关闭操作。

### 5.1 状态栏

固定显示：

- BikePower。
- 当前设备名。
- 固件短版本。
- 配网剩余时间。

剩余时间不足时才显示续期操作。上游功率计、下游 App 和未保存状态放在当前输出区，不把顶栏变成状态标签集合。

### 5.2 当前输出

当前输出区展示固件已经应用的值，不展示浏览器自行推算的假实时值：

- 骑行：功率、踏频、心率及实际来源。
- 跑步：配速/速度、步频、心率及运行/暂停状态。
- 桥接：原始输入、已应用校正输出、同源踏频和数据年龄。

存在草稿时明确显示“有未保存修改”，但已应用读数继续按固件状态更新。

### 5.3 骑行模拟输出

模拟配置合并为固定功率 / 配速机器人两项，共用踏频与模拟心率。固定模式显示目标功率；机器人模式把目标功率替换为体重，并显示强度选择及功率范围预览。自定义作为强度选项，选择后就地展开 W/kg 上下限，不再独立为第三种模式。预设和自定义共用同一配置面板。

选择联动心率时显示 FTP 与阈值心率。无关字段不占据页面。

离线原型第二版的交互约定：所有按钮文案居中；默认倒计时与续期为 5 分钟，以真实经过时间计算；面板及弹窗使用 200–240ms 淡入位移动画，遵守 `prefers-reduced-motion`。这些是原型迭代，不代表本轮已修改固件 WiFi 超时常量或配置 schema。

### 5.4 真实功率桥接

默认进入页面时不显示桥接设备、校正、真实踏频和重连内容，继续呈现旧版模拟输出配置。用户主动选择“真实功率计”后按阶段披露：

1. 只显示“选择功率计”入口，当前模拟输出继续运行。
2. 扫描并完成短时测试后，才显示设备、校正、真实踏频和模拟心率配置。
3. 保存并启用后，当前输出区才切换为桥接运行状态。
4. 已保存为桥接来源的用户再次进入页面时，直接恢复完整桥接界面。

桥接完整配置区依次显示：

1. 上游功率计和下游 App 状态。
2. 原始功率到校正输出的关系。
3. 同一功率计提供的真实踏频。
4. 已绑定设备与扫描/更换操作。
5. 原值、固定瓦数、百分比三种校正。
6. 模拟心率或关闭。
7. 可展开的重连和通知统计。

首次测试接入真实功率计时，草稿中的模拟心率及心率广播默认关闭，用户可自行打开；更换功率计、重新渲染或保存不覆盖用户手动选择。已应用的模拟输出在保存前保持不变。

来源设备区以紧凑双列展示名称、厂商、型号、序列号、硬件版本、固件版本和软件版本。增加默认未勾选的“复制设备信息到开发板”；勾选后显示开发板名称选项（功率计名称、保留原名称、自定义）及保存结果预览。无名称设备不能选择功率计名称。仅复制已读取的 DIS 字段，缺失字段显示“未提供”并保留开发板原值；不复制蓝牙地址。保存时通过 `bp_ident` 身份覆盖应用，切回模拟不自动撤销。复制后 App 可能出现同名设备，界面须提示。

手机布局参考旧版高密度设计：三项实时指标横排、参数双列、分段控件横排、减少装饰留白；字体至少 12px、输入至少 16px、主要点击区至少 44px。未启用桥接时不显示信号链路。

扫描列表只接受 CPS 功率计。无名称设备可用“未命名功率计 + 地址末尾”展示。列表使用服务端候选编号触发后续操作，不把设备名或地址拼入事件处理代码。选择桥接来源只创建草稿，不得提前显示桥接实时数据或改变已应用输出。

### 5.5 跑步输出

保留固定配速、内置配速档、自定义配速档、步频、浮动和心率。桥接只属于骑行；保存切换到跑步时必须停止上游桥接，再按既有规则重建 GATT。

### 5.6 设备面板

页面底部只保留一个低频折叠区：

- 设备名编辑。
- 按钮调功步进。
- 固件名、完整版本、板型、Git SHA 和编译时间。

该区域不恢复模板、LED、升级宣传卡片或独立子页面。

### 5.7 保存与关闭

- 有草稿时显示“保存并应用”。
- 桥接配置使用“保存并启用桥接”。
- “关闭 WiFi”使用页内二次确认，不调用 `confirm()`。
- 关闭 WiFi 不停止已经运行的桥接。
- 未保存草稿不会因关闭或超时自动提交。

## 6. 视觉与可访问性

视觉采用已确认的明主题 AI Hero Workspace：

- 页面背景 `#f1f2f5`，工作面为 `#fbfbfc` 或白色。
- 主文字接近 `#14161a`。
- 金色 `#f5c451` 仅用于主操作和当前关键来源。
- 系统字体，无外部字体文件。
- 卡片或面板圆角不超过 9px。
- 不使用渐变、装饰光斑、大面积插画和暗主题变量。

交互约束：

- 手机单列，宽屏只改变列数，不改变阅读顺序。
- 点击区域至少 44×44 CSS 像素，输入字号至少 16px。
- 状态不能只用颜色表达。
- 每秒遥测不得触发整个表单重绘或抢走输入焦点。
- 页面隐藏时停止运行状态轮询。
- 错误使用持续页内反馈；toast 只作辅助。
- 外部设备名和固件返回文本使用 `textContent`，禁止未转义 `innerHTML`。

## 7. 前端状态模型

前端仅维护三个顶层状态：

```text
applied  设备当前已应用配置
draft    用户尚未保存的编辑值
runtime  连接、遥测、数据年龄和重连状态
```

约束：

- `runtime` 更新只写只读展示节点。
- `draft` 只有用户操作、首次加载或明确恢复时改变。
- 保存成功后用服务端返回值替换 `applied`，再重建 `draft`。
- 保存失败保留 `draft`。
- 请求超时且结果不明时，重新读取 revision 和已应用配置核实，不盲目重复提交。

## 8. HTTP 接口

### 8.1 保留和新增

| 方法 | 路径 | 用途 |
|------|------|------|
| GET | `/api/state` | 首次加载能力、配置、revision 和运行摘要 |
| GET | `/api/runtime` | 紧凑运行状态、剩余时间和空闲堆 |
| POST | `/api/config` | 带 revision 的完整配置事务 |
| GET | `/api/bridge/scan` | 扫描进度和候选列表 |
| POST | `/api/bridge/scan` | `start` / `stop` |
| POST | `/api/bridge/control` | `test` / `start` / `stop` / `cancel` |
| POST | `/api/renew` | 延长本次配网时间 |
| POST | `/api/close-wifi` | 保存后或单独关闭 WiFi |

Captive Portal 的系统探测路由继续保留。

### 8.2 删除或合并

- 删除全部 `/api/device-templates*`。
- 删除旧 `/api/ble-scan/read` 和 `/api/ble-scan/analyze`。
- 旧 `/api/ble-scan/start|stop|results` 由 bridge scan 接口替代。
- `/api/time` 合并到 `/api/runtime`。
- `/api/mem_stats` 合并到 `/api/runtime`，不再单独轮询。

### 8.3 接口约束

- 长操作只接受命令并快速返回，不阻塞 HTTP 请求等待 BLE 连接。
- 扫描响应只返回候选编号、显示名、RSSI、地址末尾和能力，不返回可被前端拼接执行的内容。
- 每个请求体和响应都有编译期上限。
- 同一时刻最多一个 runtime 请求和一个桥接命令。
- 服务端对所有范围、字符串长度、UTF-8、revision 和状态前置条件重新校验。

## 9. 保存与桥接生效语义

“保存并启用桥接”分为：

1. `POST /api/config` 保存来源、绑定和校正参数。
2. 保存成功后调用 `POST /api/bridge/control` 的 `start`。
3. 页面轮询直到收到有效数据或明确失败。

如果第 1 步成功、第 2 步失败，页面显示“配置已保存，桥接未启动”，并提供重试。不能把两种结果折叠成“保存失败”。

测试连接是临时会话：

- 不修改已应用来源。
- 不写 NVS。
- 最长 30 秒。
- 测试结束释放连接，或在启用时由持久桥接会话安全接管。

切回模拟或跑步时，配置应用负责先停止桥接，再切换输出和必要的 GATT 服务。停止桥接不清除绑定和校正参数。

## 10. 配置与迁移

当前配置已为 v12；升级到 v13，增加独立 bridge 配置组，并保留 v11→v12 的历史功率浮动迁移：

- 骑行来源：模拟 / 真实桥接。
- 是否存在有效绑定。
- 上游地址及地址类型。
- 仅用于显示的设备名称。
- 校正模式：原值 / 固定瓦数 / 百分比。
- 固定偏移：`-200..200 W`。
- 百分比调整：`-500..500`，单位 `0.1%`。

百分比计算只用整数：

```text
输出 = round(输入 × (1000 + percent_x10) / 1000)
```

迁移要求：

- v12 升级后默认模拟来源、无绑定、原值转发；更早版本先执行既有逐级迁移。
- 不因升级自动扫描或连接。
- 一次性清理旧 `ble_tpl` NVS namespace，回收模板槽位。
- 保留 `bp_ident` 身份覆盖 namespace，确保 Pages 的 DIS profile 写入继续有效。
- LED 配置和 BLE LED 特征继续存在。

BLE 配置协议增加独立 bridge 特征和 group mask 位。Pages 必须按能力位显示桥接字段；旧固件不支持时显示明确原因。

## 11. 桥接运行时

连接资源固定为：

- 一条下游 BikePower peripheral 连接。
- 一条上游功率计 central 连接。

规则：

- 首版只连接一个 CPS 功率计。
- 更换设备前先释放旧上游连接。
- 不在桥接期间运行旧模板分析或第三条 central 连接。
- 启动后至少收到两份有效功率通知才进入数据有效状态。
- 有效 0 W 是有效样本。
- 明确断线时立即输出 0 W 并使真实踏频失效。
- 连接仍在但 3 秒没有新功率时执行相同过期保护。
- 10 秒无有效功率时主动断开并进入重连。
- 重连窗口 60 秒，间隔 1、2、4、8 秒，之后保持 8 秒。
- 冷启动只恢复绑定与配置，状态为待启动，不自动连接。

同源踏频只来自 CPS 曲柄字段。无曲柄字段、重复事件、非法时间差、数据过期或断线时不发送真实踏频，也不回退到模拟踏频。

桥接模式的模拟心率：

- 首次接入默认关闭，用户手动开启后才输出心率。
- 固定心率在功率断线时继续。
- 联动心率使用有效原始功率，不使用校正后功率。
- 原始功率失效时按零负荷平滑回落。

## 12. 功率校正

校正顺序：

1. 检查样本有效性和年龄。
2. 输入小于等于 0 W 时输出 0 W，不叠加正偏移。
3. 正功率按已应用模式计算。
4. 按最近整数瓦舍入。
5. 夹紧到 `0..2000 W`。

页面必须区分：

- 原始输入。
- 固件已应用输出。
- 未保存参数的草稿预览。

无实时输入时，草稿预览可以使用明确标注的 200 W 示例，不得冒充设备读数。

## 14. 资源预算

构建产物按 `scripts/inline_static.py` 生成后的 `index_html_len` 计量：

| 项目 | 目标 |
|------|------|
| HTML | ≤16 KiB |
| CSS | ≤20 KiB |
| JavaScript | ≤54 KiB |
| 总量工程目标 | ≤90 KiB |
| 预警线 | 100 KiB |
| 硬门禁 | 110 KiB |

构建脚本必须输出分项、总量和节省量；超过 110 KiB 直接失败。

运行时要求：

- HTML 从 flash 直接发送，不整页复制到堆。
- runtime 响应目标小于 1 KiB。
- 扫描候选保持有界。
- WiFi + 上游 BLE + 下游 BLE 并行时空闲堆始终大于 80 KiB。
- 通知、GATT 回调和扫描回调不分配大缓冲。

## 15. 错误与安全

- 外部文本使用 DOM 文本节点，服务端输出仍需 JSON 转义。
- 非法、空白、越界输入显示字段级错误并禁用保存。
- 旧固件缺少桥接能力时隐藏写操作并说明升级要求。
- runtime 连续 3 秒失败后把页面标为过期，不继续宣称实时。
- App 已连接、已订阅、通知已提交分别展示，不宣称 App 已显示数据。
- 配网关闭、网页断开和上游功率计断开是三个不同状态。
- 扫描、测试和重连不自动延长 WiFi 配网时间。
- ISR 和 NimBLE 回调只做有界解析或投递，不调用阻塞、HTTP、NVS 或普通日志 API。

## 18. 验收标准

本设计完成实施必须同时满足：

1. 门户构建后不超过 110 KiB，且没有暗主题、旧模板或 LED 门户代码。
2. 用户可在单页完成模拟骑行、跑步和真实功率桥接的现场操作。
3. 设备名、按钮步进和固件详情仍可在门户使用。
4. Pages 可继续通过 BLE 管理 LED 和完整配置。
5. 旧 `ble_tpl` 数据完成一次性清理，`bp_ident` 身份覆盖保持兼容。
6. 桥接断线或数据过期不会继续输出旧功率或模拟踏频。
7. WiFi、上下游 BLE 并行真机门禁通过，空闲堆不低于 80 KiB。
8. 所有领域、协议、门户、双板构建和真机验证均有可追溯证据。
