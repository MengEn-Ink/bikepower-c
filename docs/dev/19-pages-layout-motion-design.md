## 方向比较

1. 推荐：保留现有工具台视觉语言，重新组织导航和配置分区，增加状态驱动的轻量动效。改动范围可控，适合现有多工具功能。
2. 向导式布局：按安装、连接、配置、诊断串联流程。新用户容易理解，但反复切换工具的操作成本较高。
3. 仪表盘布局：全部工具和配置并排展示。数据集中，但长表单和窄屏布局更容易拥挤。

## 推荐布局

导航划分为三个清晰的区域：上手（使用手册、固件刷写）、设备（实时监控、设备比对）、诊断（通知检查器、健康检查）。保留已有工具和入口，当前区域与当前工具均有明确选中态。

监控页按设备连接摘要、实时运动数据、设备配置、诊断信息排列。桌面端以主内容和辅助信息形成层次，手机端单列展示。辅助日志默认收起。

设备配置按任务拆分为设备身份与广播、输出来源与功率桥接、骑行参数、跑步参数、个人资料、按钮与 LED。常用配置优先展示，其他分区折叠；骑行与跑步相关内容随运动 Profile 渐进展示。隐藏字段仍保留值，保存事务不丢失现有配置。

桥接选项按模拟、真实来源分阶段展示。真实来源显示已绑定设备、连接状态和校正设置；未绑定时明确引导到设备配网页扫描测试。状态与数值均来自实际数据。

保存区集中放置保存按钮、未保存提示和结果反馈，读取、恢复、导出作为次级操作。

## 视觉与动画

- 延续现有品牌和主题，用字号、留白、边界与少量强调色建立层次，保证浅色和暗色主题的正文、控件及状态提示可见。
- 工具切换采用约 180–240ms 的淡入与轻微位移。
- 分区展开采用轻量过渡，确保焦点与键盘操作不受影响。
- 按钮提供悬停、按压反馈；保存中、保存成功与失败显示不同状态。
- 连接过程使用已有扫描视觉，连接完成给一次短反馈；连接稳定后避免持续装饰动画。
- 实时数据更新仅短暂强调发生变化的数值，不制造数据或改变数据含义。
- 支持 `prefers-reduced-motion`，减少动画时仍完整显示状态。
- 动画优先使用 opacity 和 transform，避免影响实时绘图性能。

## 页底更新信息

桌面工具台和手机介绍页均显示“页面更新发布时间”、时区和源码短提交号。

构建流程生成独立页面元数据，包括源码提交、页面构建时间。时间定义为本次成功发布所使用页面的构建时间，不能把用户打开页面的当前时间当作发布时间。UI 使用北京时间并明确标注时区。真实部署完成时间若需展示，必须另接部署完成后的可靠元数据，不能用构建时间冒充。

固件发布时间继续使用 GitHub Release 时间，名称与页面更新时间分开，避免混淆。

本地预览缺少元数据时显示“本地预览 · 未发布”。加载失败时显示“更新信息暂不可用”，不编造日期。
