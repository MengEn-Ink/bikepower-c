# Pages 蓝牙连接异常分类与恢复

## 原则与变更边界

连接失败必须同时告诉用户：当前发生了什么、已知与未知、下一步点哪里、仍失败需保留什么。不得把通用 `Connection attempt failed` 一律归因“其他 App 占用”或“Windows 缓存”。浏览器网页无法读取系统 HCI 或开发板 NVS，仅凭泛化 NetworkError 不可断言绑定丢失。

本次只改 Pages 指引及回归。固件、NVS schema、MAC、刷机写入范围保持。全量合并 BIN 覆盖 NVS 的问题仅如实提醒，未改为保留式升级；不新增自动清配对或自动换 MAC。

## 异常分类与解决方案

### 1. 未选择设备 / 选择器取消
- 判据：设备选择阶段的 `NotFoundError`、User cancelled；不套用到服务读取阶段的 NotFoundError。
- 提示：尚未建立连接，不是开发板故障。
- 操作：重新点“扫描并连接设备”，选择当前 BikePower 后确认。列表为空时检查供电、广播、距离，释放确实占用的连接；刷后等待启动，无广播再按 EN/RST 或重新上电，非恢复出厂。

### 2. 权限未允许
- 判据：SecurityError / NotAllowedError、明确蓝牙访问拒绝。
- 操作：桌面 Chrome/Edge、HTTPS、主动点击；检查地址栏站点蓝牙授权。Mac 检查“系统设置 → 隐私与安全性 → 蓝牙”中的浏览器权限。管理策略拒绝时联系管理员，不绕过。

### 3. 浏览器 / 安全上下文不支持
- 判据：Web Bluetooth 不存在，或非安全上下文。
- 操作：桌面 Chrome/Edge 直接打开 HTTPS。Safari/Firefox/iOS 不走本工具网页 BLE；手机配置走开发板热点 192.168.4.1。API 存在不代表权限或 GATT 建链成功。

### 4. 蓝牙适配器关闭 / 不可用
- 判据：明确 powered off / unavailable；不以通用 NetworkError 推断。
- 操作：检查系统蓝牙与适配器，再扫描；不修改板端 MAC/配置。

### 5. 旧配对信息失效 / 密钥不一致
- 判据：Peer removed pairing information、PIN/Key Missing 等明确错误；Code14 本次由 Mac 独立诊断确认，网页可能只显示泛化错误。
- 背景：当前 v4.4.1 合并文件的 0x9000–0xEFFF 为 FF，从0x0连续写入会覆盖 NVS 配置与绑定，不勾整片擦除也不保留。电脑旧配对仍在，可形成单边绑定。
- 操作：只处理这一台 BikePower。Mac“系统设置 → 蓝牙 → BikePower 详情 → 忽略此设备”；Windows“设置 → 蓝牙和设备 → 设备 → BikePower → 删除设备”。回 Pages 重新选择确认。普通传感器读取不必先主动系统配对。
- 风险边界：未刚全量刷机、也无明确配对错误时，不直接删绑定；板端仍有旧记录的情况需维护人员核对。不要整片擦除、清空全部配对或自动改 MAC。

### 6. 前一次连接仍在建立 / 收尾
- 判据：页面连接互斥仍持有。
- 操作：等待，不重复点击/多窗口抢连；长期悬挂先保留日志，只关闭当前设备页再重新连接。保留原超时取消栅栏和代次隔离。

### 7. 目标 App 实测暂停
- 判据：网页 BLE 暂停状态。
- 操作：完成实测、释放该 App，点击“结束实测，恢复网页连接”，再主动选设备。不静默恢复抢占。

### 8. 刷写 / 串口会话未结束
- 判据：安装或日志会话仍忙。
- 操作：等待真实终态与串口释放，再连 BLE。写入100%或弹窗关闭不代表安装成功。

### 9. 握手超时
- 判据：页面有界等待超时。
- 提示：仅本次等待失败，底层可能仍收尾；不证明服务缺失或占用。
- 操作：待收尾、检查供电/距离/确实占用；刚全量刷机且曾系统配对时条件性走旧配对流程。仍超时提供原始错误、事件日志、系统/浏览器、版本、刷机方式。

### 10. 建链后断开
- 判据：GATT disconnected、链路关闭。
- 操作：检查供电/距离/复位，配置后预期GATT重建先等待。断开后系统可能延迟释放旧链路，稍候无广播再 EN/RST 或上电。历史数据不可冒充实时输出。

### 11. 服务枚举未完成 / 旧服务表待核
- 判据：service discovery failed、枚举异常；不直接定为缓存或缺服务。
- 操作：重选授权，核对模式/广播/来源。连接稳定但仍旧服务表时保留证据核对缓存/Service Changed。DIS 可选字段缺失不影响已确认正常的运动通知。

### 12. 枚举完成却无可用运动服务
- 判据：成功完成的服务发现没有运动或明确授权参考服务；枚举失败/断连不能用此分类。
- 操作：核对所选设备、固件与模式。默认踏频随功率可不暴露 CSC；功率连接 CPS/FTMS 带踏频。跑步RSC、骑行FTMS和HRS取决于模式/开关，不能因一个可选服务缺失就重刷。

### 13. 已连接但无新通知
- 判据：订阅失败、通知新鲜度超限或数据长期不更新。
- 操作：看 CPS/HRS/FTMS 订阅与最后通知、输出开关、实际来源，真实功率计先唤醒。第三方App功率/踏频正常但不读HRS时单独检查其角色策略；骑鬥需心率可用独立心率带。不可把客户端策略混同全链路建链失败。

### 14. 已授权列表 / 自动重连能力不可用
- 判据：getDevices不存在或站点无授权。
- 操作：主动“扫描并连接设备”重新选中确认。能力不可用时不承诺免弹窗重连；重试耗尽可见提示手动选择和条件性旧配对处理。

### 15. 通用连接失败：原因未知
- 判据：Connection attempt failed、未知 GATT/NetworkError。
- 首屏：原因未确定；供电/距离/占用/系统/旧配对不能单独定性。
- 步骤：先检查供电、接近并核对当前设备；只释放确实占用它的 App/页面。若刚全量刷机/恢复出厂且曾系统配对，则定向忽略/删除旧 BikePower 再选。没有该前提不清绑定。仍失败保留日志与版本/环境/刷机方式。

## 页面落点

- 首次连接门：中文分类标题、简短说明、直接可读的有序操作步骤；原始错误放折叠技术信息，经过HTML转义。
- 实时监控侧栏：同一规则分类，失败/断开/通知超期均有可见恢复步骤；通知恢复后清除过期提示。
- 设备比对/通知检查入口：连接失败不只留裸英文日志。
- 安装后衔接：说明全量合并固件会覆盖NVS，刚刷机旧配对问题的Mac/Windows入口。
- 桌面手册：单一折叠分类入口，15类来自同一catalog；手机首屏保持精简，不重复堆叠FAQ。
- 不新增设备写入、清配对按钮或MAC变更；外部系统步骤由用户操作。
