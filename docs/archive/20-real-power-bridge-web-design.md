# 真实功率桥接与网页交互设计

> 归档于 2026-11-05：阶段桥接方案已被 [当前技术参考](../dev/01-technical-reference.md) 与 [三设备主备规范](../dev/28-bridge-failover-multi-device-design.md) 吸收；以下单设备等描述为历史方案。

日期：2026-11-04

状态：设计提案，待审阅；尚未实施或完成真机验证。

范围：单个 BLE 功率计接入、真实功率与同设备真实踏频桥接、功率校正、断线保护和配网页实时监测；心率独立选择模拟输出或关闭。

范围收敛：网页只绑定一个功率计，不单独扫描或连接踏频计、心率带；功率计在 CPS Measurement 中携带的曲柄数据必须解码为真实踏频并随功率一起桥接。设备不提供曲柄数据时显示“未提供踏频”并停止踏频输出，不用模拟踏频补位。功率计可能携带的心率不桥接，心率仅模拟或关闭。

当时门户职责、信息架构、资源预算、模板删除和 Pages 分工见 [核心设备门户全量重写设计](21-core-portal-rewrite-design.md)。两份归档均不作为当前实现依据。

## 1. 推荐方案与依据

推荐沿用现有首页的“骑行输出”，默认保持旧版模拟输出。只有用户主动选择“真实功率计”后才显示桥接入口；测试设备通过后再增量展示连接状态、真实功率、同设备真实踏频和功率校正。心率保留模拟或关闭。已保存桥接来源的用户再次进入时直接恢复完整桥接界面。

| 方案 | 用户体验 | 实现与维护 | 结论 |
|------|----------|------------|------|
| 首页功率来源切换＋同页桥接面板 | 数据与校正同时可见，常用操作路径短 | 复用首页、模拟配置卡片和保存流程 | 推荐 |
| 独立“桥接”底部导航页 | 功能隔离明确，但模式与桥接状态分散 | 增加跨页状态、入口与保存同步 | 暂不采用 |
| 每次都走连接向导 | 首次容易理解，日常调参步骤多 | 向导退出与恢复状态复杂 | 仅首次使用借鉴 |

用户是在短时本地配网过程中完成设备选择和调参，随后关闭 WiFi 继续骑行。首屏应回答三个问题：数据从哪里来、校正后是多少、是否正在向 App 输出。

现有代码依据：

- `main/web/index.html`：首页已有骑行/跑步选择、骑行输出来源、广播数据项和保存操作；设置已有设备模板子页。
- `main/web/app.js`：来源点击只修改草稿，保存时提交完整配置；关闭 WiFi 使用页内二次点击确认；配网剩余时间可手动续期。
- `sdkconfig.defaults`：启用 central/peripheral/observer，总连接上限为 2。
- `main/ble_scanner.c`：已有扫描、外部连接与短时通知采样；临时采样不是持续桥接。
- `components/bikepower_domain/device_analysis.c`：CPS 功率解析仍需按规范完善，不能直接作为生产桥接解码器；生产解码器还需按 CPS flags 解析累计曲柄转数和最后曲柄事件时间，并处理回绕、停踩与异常时间差。
- `components/bikepower_domain/power_engine.c`：已有模拟踏频浮动、固定心率浮动和功率联动心率；真实功率计路径需要绕过模拟功率和模拟踏频，只保留可选的模拟心率。
- `main/ble_bikepower.c`：当前曲柄累计量与 FTMS 速度由模拟踏频推演；桥接模式需改为使用上游真实踏频状态，并在上游未提供或失效时停止声明对应字段。

## 2. 首页信息架构

保留骑行/跑步入口。骑行输出内增加功率来源选择：

- 模拟输出：展开现有“固定 / 配速机器人 / 自定义”选项，并沿用模拟踏频与模拟心率配置。
- 真实功率计：展开桥接面板，不显示固定功率、功率浮动或模拟踏频编辑器；踏频固定跟随同一功率计，心率保留模拟或关闭。

功率来源与原模拟模式分开建模。模拟模式保留原值，切回模拟时恢复；切入桥接时不把校正偏移写入 `base_power`，也不覆盖已保存的模拟踏频参数。桥接模式不读取这些模拟踏频参数，心率配置继续独立生效。

三个数据项按功率来源联动：

| 数据项 | 可选来源 | 配置入口 |
|--------|----------|----------|
| 功率 | 模拟输出 / 真实功率计 | 功率来源选择器与桥接面板 |
| 踏频 | 模拟模式下按原配置；桥接模式下固定为同一功率计真实踏频 / 设备未提供 | 不单独选设备；桥接面板只读展示能力和实时值 |
| 心率 | 模拟 / 关闭 | 现有心率广播开关；启用后展示模拟模式与参数 |

桥接模式不能手动把踏频改成模拟值。设备不提供 CPS 曲柄数据时显示“此功率计未提供踏频”，对应 CPS/CSC/FTMS 踏频字段停止输出。心率关闭后收起编辑器并保留参数；重新启用时恢复参数。点击心率开关仍只改草稿，保存后才影响实际输出。

桥接面板从上到下：

1. 实时状态：功率计、App 两侧连接状态。
2. 核心读数：真实功率输入 → 已应用校正输出、真实踏频、数据更新时间；心率另行标注“模拟”或“关闭”。
3. 来源设备：名称、地址末尾、功率与踏频能力；选择设备、开始连接或停止桥接。
4. 功率校正：模式、参数、公式、草稿预览。
5. 同源踏频只读状态、模拟心率配置卡片。
6. 功率与踏频保护说明及可展开的监测详情。
7. 页面底部保存操作和关闭 WiFi 操作。

广播数据项随来源变化：

- 功率：桥接必需，保持启用；只有暂停桥接或切回模拟才能停止整条输出链路。
- 踏频：桥接模式固定使用同一功率计携带的真实曲柄数据，不提供第二个设备入口，也不提供模拟回退。设备未提供时显示不可用并停止对应字段。
- 心率：独立选择模拟或关闭；不提供扫描、绑定、设备连接入口。启用时明确显示“模拟心率”。
- 首次切入真实功率计时，踏频来源自动锁定为“同一功率计”，已保存的模拟踏频参数仅为切回模拟模式保留；心率沿用现有开关和参数。用户可保存“真实功率＋真实踏频＋模拟心率”或关闭心率。
- 进入跑步页面可编辑草稿；实际保存切换运动类型时，先显示页内确认，说明将结束当前桥接和必要的 BLE 服务重建。

## 3. 首次配置流程

### 3.1 选择真实来源

点击“真实功率计”只打开配置草稿，不改变正在运行的输出。若仍处于模拟输出，顶部显示“当前仍在模拟输出，启用桥接后切换”，不能提前显示为真实数据。

未绑定设备时：

- 标题：“选择你的功率计”。
- 说明：“转动曲柄唤醒设备；如果无法连接，请先断开其他 App 对功率计的占用。”
- 主操作：“扫描功率计”。
- 页内展示扫描进度与取消操作，复用现有 8 秒限时扫描。

### 3.2 扫描与选择

首版选择列表只接收可识别的 CPS 功率计；FTMS 骑行台输入属于后续扩展。不能把所有骑行服务命中的普通扫描结果都当成功率来源。

每行显示：

- 设备名称；无名称 CPS 设备以“未命名功率计 · 地址末尾”展示。
- 信号强度和地址末尾，避免同名设备混淆。
- “功率＋踏频”或“仅功率”能力；踏频能力来自同一 CPS 设备的曲柄字段，不把独立踏频计或心率带列为候选。
- “选择并测试”操作。

桥接专用扫描允许无名称 CPS 设备，以“未命名功率计 + 地址末尾”展示。旧设备模板库按 15 号设计删除，不再保留第二套筛选规则。

选择后按“连接中 → 发现服务 → 订阅中 → 等待数据”显示明确进度；每一阶段都能取消。HTTP 操作接受后即返回，由页面轮询进度，不能让请求阻塞等待长时间采样。

连接成功不等于数据有效。收到至少两份有效功率通知后，才能显示“测试成功”。持续收到有效 0 W 也算成功；不能把零功率误判为无数据。若通知声明曲柄字段，测试区同步显示真实踏频；尚未形成有效事件差时显示“等待踏频”，不能填充模拟值。

### 3.3 测试与启用

测试连接为短时预览会话，最长 30 秒，不能自动把测试数据切入当前输出，也不能保存设备绑定。测试到期后释放上游连接，草稿中保留选择结果。

测试成功后展示真实原始功率和同源踏频能力。校正默认“原值转发”，按需修改。真实踏频只读；模拟心率在独立卡片中设置。主操作变为“保存并启用桥接”。

首次测试期间，测试输入与校正预览标注“测试数据”；实际输出区域明确标注当前实际来源，仍在模拟时不能用测试功率冒充正在发送的值。

后端先验证并保存配置，再启动桥接会话。只有运行状态确认后，页面才能显示“桥接已启用”。保存成功但连接尚未完成，应显示“配置已保存，正在连接”；启动失败应显示具体原因及“重试连接”，不能伪装成保存失败。

如果测试仍在线，启用时可由桥接状态机接管该连接；测试已到期则重新连接已选设备。接管必须更换成持久上下文，不能继续引用 HTTP 请求栈上的对象。

此前正在模拟输出时，实际切入桥接从成功保存开始：等到新的有效数据前功率输出 0 W，踏频保持无效，不继续模拟。

## 4. 已配置用户的日常操作

保存过设备后直接显示设备名称、已保存校正参数与当前运行状态。

| 操作 | 行为与反馈 |
|------|------------|
| 开始桥接 | 使用已保存设备与参数启动当前会话，不扫描全部附近设备 |
| 编辑校正 | 仅修改本地草稿；显示“未应用修改”，实际输出仍用已保存参数 |
| 保存并应用 | 校验、保存、应用成功后更新实际输出；下一次 BLE 通知使用新参数 |
| 停止桥接 | 页内二次点击确认；结束上游连接和重连任务，真实功率归零且真实踏频失效；固定模拟心率继续，联动心率按零负荷回落；设备绑定与参数保留 |
| 更换设备 | 活跃会话先确认“停止当前功率桥接并选择新设备”；确认后功率归零并释放上游连接，再扫描 |
| 取消更换 | 保留原绑定与参数；若旧会话已停止，明确提供“恢复原设备连接”，不能声称仍在线 |
| 切回模拟 | 先编辑草稿；保存时页内确认会停止桥接并应用模拟配置 |
| 保存并关闭 WiFi | 成功保存后关闭网页服务，已运行桥接继续；没有运行会话时提示“尚未启动桥接”并要求确认 |

首版运行会话不持久化。冷启动后仅恢复设备绑定、校正和来源设置：

- 保存来源为模拟时，沿用现有模拟启动流程。
- 保存功率来源为桥接时，进入“待启动”，功率输出 0 W、真实踏频无效，正常提供下游 BLE 发现能力；固定模拟心率按已保存设置运行，联动心率使用零负荷输入。用户通过现有按钮流程打开配网页并点击“开始桥接”。
- 不在开机时后台扫描附近设备。开机自动连接属于后续单独设计，不能由“记住设备”隐式引入。
- 网页关闭、配网到期与设备重启不同；关闭网页不会结束已启动的桥接会话。

## 5. 校正编辑与应用语义

首版只提供三种模式，不同时展示两项容易混淆的参数：

| 模式 | 页面字段 | 公式 | 设计示例 |
|------|----------|------|----------|
| 原值转发 | 无 | 输出 = 输入 | 200 W → 200 W |
| 按瓦数 | 调整瓦数，带 W 单位 | 输出 = 输入 + 偏移 | +20 W：200 W → 220 W |
| 按百分比 | 调整比例，带 % 单位 | 输出 = 输入 × (1 + 比例 / 100) | +10%：200 W → 220 W |

比例必须填写 `+10%`，不使用截图里含义不明确的 `0.1`。正值增加、负值降低，在字段旁明确说明。

建议参数范围：瓦数 -200 至 +200 W，步进 1 W；比例 -50% 至 +50%，步进 0.1%。这是首版设计建议，实施时统一加入领域常量与校验，不能当作现有约束。输出沿用当前 0 至 2000 W 的范围。

计算顺序：

1. 先检查输入有效性和采样年龄；无效输入不能进入校正公式。
2. 有效输入小于等于 0 W 时输出 0 W，不叠加正偏移。
3. 对有效正功率执行所选公式，按最近整数瓦舍入。
4. 超过输出范围时夹紧，并显示“输出触及范围限制”；输入异常与输出夹紧分别记录。

必须区分三组数据：

- **原始输入**：设备最新有效通知，带采样年龄。
- **已应用校正输出**：固件基于已保存参数的当前输出快照，页面不能自行算好后充当固件输出。
- **草稿预览**：页面按未保存参数计算，标明“预览，尚未应用”；无有效原始数据时使用明确标注的“示例输入 200 W”，不能当作实时值展示。

输入非法、空白或越界时，在字段下显示具体原因并禁用保存，不默默改成 0 或合法上限。改变校正模式保留各模式草稿值；“原值转发”绕过校正，保留已填参数以便再次使用。

运行数据轮询不能覆盖正在编辑的参数。保存失败保留草稿，旧配置与旧实际输出继续有效。保存请求超时但结果不明时，先读取配置版本和设备回执核实，不能直接宣告失败或盲目重复应用。

## 6. 真实踏频、模拟心率与协议输出

上游发现并订阅所选功率计的 CPS Measurement，读取真实瞬时功率及同一通知中的累计曲柄转数、最后曲柄事件时间。首版不绑定第二个 CSC 踏频设备，也不订阅真实 HRS。

### 6.1 同源真实踏频

- 踏频只来自同一功率计 CPS Measurement 的曲柄字段，不提供独立扫描、手动来源选择或模拟回退。
- 解码器根据相邻累计曲柄转数和最后曲柄事件时间计算 rpm，并正确处理 16 位回绕、重复样本、非法时间差和停踩。
- 功率通知未声明曲柄字段时，页面显示“设备未提供踏频”，对外停止 CPS 曲柄可选字段、CSC 通知和 FTMS 踏频字段。
- 功率数据过期、上游断开或会话停止时，真实踏频同步失效；不得保留最后 rpm，也不得切换到已保存的模拟踏频。
- 模拟模式下原有模拟踏频配置保持不变；在桥接模式中只保留其草稿，切回模拟并保存后才重新生效。

### 6.2 模拟心率

- 开关沿用现有心率广播开关，界面明确标注“模拟心率”。
- 启用后复用现有两种配置：固定模拟心率（目标 bpm 与浮动）和随功率联动的模拟心率（按 FTP、阈值心率等模型生成）。
- 功率联动在桥接模式中使用**有效原始功率**作为负荷输入，不使用校正后的功率，避免只改偏移就人为改变模拟心率负荷。
- 原始功率为零或失效时，联动模型使用零负荷输入并按既有平滑机制回落，不能冻结最后的高功率负荷，也不能把心率瞬间归零。
- 固定模拟心率在功率断线时继续按固定配置输出。关闭心率时停止 HRS 通知，并省略 FTMS 心率字段。
- 不增加第三种模拟算法，不扫描或连接真实心率带；各模拟参数保留独立配置。

### 6.3 对外协议

对外仍维持 cycling 的 CPS/HRS/CSC/FTMS/DIS 服务组合；首版桥接提供同源真实功率与真实踏频，不提供真实心率或骑行台控制。

- CPS 的瞬时功率来自已应用校正；上游曲柄数据有效时，输出侧以本地连续状态转发对应曲柄累计量和事件时间，不能混入模拟踏频。
- CSC 只在同源真实踏频有效时发送曲柄数据；上游没有曲柄能力或数据失效时停止通知。
- HRS 仅在模拟心率启用时发送；关闭时停止通知。
- FTMS 组合真实校正功率、有效真实踏频与可选模拟心率，flags 与实际字段严格一致。
- 不再由模拟踏频推演 FTMS 速度；首版没有真实速度输入时，桥接模式省略速度或按协议能力明确处理，不能把估算值标成真实速度。
- 复核功率单独、功率＋真实踏频、功率＋模拟心率、功率＋真实踏频＋模拟心率四种输出组合，同步 codec、golden vectors、自测脚本和 BLE 规则。
- 桥接模式中 `SetTargetPower` 等控制真实负载的请求返回不支持，不能偷偷转入模拟 ERG；其他控制点行为也不能修改原始功率或校正参数。
- 用户切换 GATT 可见能力若需重建，页面先解释 App 会暂时断开；重建必须通过现有 `radio_ctrl` 路径协调上游与下游会话。

首页注明：“在骑行 App 中选择 BikePower 作为功率来源；盒子首版只转发数据，不控制骑行台阻力。”

## 7. 断线保护与状态反馈

建议首版功率数据过期阈值 3 秒；断线后的重连窗口 60 秒，尝试间隔 1、2、4、8 秒，后续保持 8 秒且不越过窗口。均为待验证的设计值。

| 状态 | 核心读数 | 页面文案与操作 |
|------|----------|----------------|
| 未选择设备 | 输入 —，桥接输出 — | “先选择功率计”；扫描 |
| 已绑定、待启动 | 输入 —，输出 0 W | “点击开始桥接”；开始 |
| 连接/订阅中 | 输入 —，输出 0 W | 明确阶段；取消 |
| 已连接、等待功率 | 输入 —，输出 0 W | “转动曲柄，等待功率通知”；10 秒未收有效数据后提示检查占用/协议 |
| 数据有效 | 显示有效功率输入、校正输出与真实踏频 | 各字段更新时间、心率模拟标签与两侧状态 |
| 连接尚在、功率超过 3 秒未更新 | 当前输入 —，输出 0 W | “功率数据已过期，已停止使用旧值”；历史最后读数仅放详情 |
| 上游已断开、重连中 | 输入 —，输出 0 W | “功率计断开，正在重连，剩余 Ns”；停止重连 |
| 重连窗口结束 | 输入 —，输出 0 W | “未能恢复连接”；重新连接 / 更换设备 |
| App 未连接或未订阅 | 保留有效输入与固件校正值 | “App 尚未接收”；显示配对指引，不把上游判为失效 |
| 网页连接丢失 | 标记最后画面已过期 | “网页连接中断，当前桥接状态未知”；停止把旧画面当实时状态 |
| 用户停止 | 输入 —，输出 0 W | “桥接已停止”；开始 |

上游明确断开时功率立即归零、真实踏频立即失效，不等待 3 秒。连接尚在但通知停滞时，过期立即执行同一保护，并在 10 秒无有效功率时主动断开进入相同重连流程，避免永久挂在“已连接”。

重连只针对用户启动会话中绑定的设备。不持续发现其他设备，也不自动换源。随机地址无法稳定再次连接时说明原因，要求用户重新扫描选择；不能仅凭同名设备认定身份相同。

恢复至少两份新的有效功率通知后再启用校正输出，下游保持连接，源恢复后无需用户重新配对。真实踏频需重新形成有效曲柄事件差后才恢复；固定模拟心率继续按配置运行，功率联动模拟心率按零负荷平滑回落，恢复有效功率后继续跟随。

首版不提供“断线切回模拟”“保持最后功率”“保留正偏移”选项，避免数据失效后继续产生有效功率。用户明确切换来源是另一项操作。

## 8. 实时监测与网页生命周期

首屏显示真实功率输入、已应用校正输出、同源真实踏频、字段数据年龄和两侧状态；心率显示“模拟：数值”或“已关闭”，不能与真实数据混淆。详细诊断折叠，展开后显示：

- 来源名称、地址末尾、可用协议字段。
- RSSI 的采集时间；不能把扫描时 RSSI 当作当前连接信号。
- 最近有效真实功率和曲柄采样时间、收到通知数、曲柄事件差、丢弃/解析错误数；模拟心率显示当前配置与输出值，不虚构外部采样时间。
- 最近一次重连原因、当前尝试次数、剩余窗口。
- 最近通知提交值与时间、失败计数、App 订阅状态。
- 当前实际来源、已保存配置版本、草稿是否未应用。

“App 已连接”“已订阅”“通知提交成功”三者分别显示。BLE notification 没有应用级接收确认，页面不能宣称 App 已经显示该读数；若需要验证 App 显示，要由用户或外部验收工具检查。

网页可见且停留桥接面板时每秒轮询一次紧凑状态；同一时间最多一个监测请求。页面隐藏、离开面板、进入关闭流程时停止该轮询。失败按 2、4、8 秒退避，恢复后先读取完整当前状态。

网页连续 3 秒未取得状态时，将画面标为过期，不再宣称“实时”。浏览器不能据此判断设备端是否已归零，必须显示“当前桥接状态未知”。

曲线若启用，仅在“监测详情”内展示最近 60 秒输入/输出对比，由浏览器维护有界缓存；数据失效画缺口，不能插值补齐。首版不引入外部图表库或设备长期存储。

配网沿用现有 180 秒有效期和手动续期：

- 剩余 60 秒内显示现有续期按钮，并说明“续期仅延长网页访问，不保存修改”。
- 不因为监测轮询、扫描或上游重连自动延长 WiFi 会话。
- 如果有效期不足以完成测试，先提醒续期；接受扫描/测试前需给出清晰剩余时间。
- 关闭 WiFi 前展示“网页将关闭，已启动桥接继续运行”；未启动会话则展示实际情况。
- WiFi 到期只停止网页服务和未提交的测试/扫描会话，不结束已启用的桥接。
- 设备上游连接、校正、保护和重连由固件运行，不依赖浏览器轮询。

## 9. 视觉与可访问性

当时门户视觉见 [核心设备门户全量重写设计](21-core-portal-rewrite-design.md) 的明主题 AI Hero Workspace。主强调色只用于当前来源、主操作和必要状态，配置区以结构线分段，不堆叠悬浮卡片。

- 手机单列：先读数与状态，再设备和校正。较宽屏幕可把监测与配置并排，但不改变阅读顺序。
- 使用明确文字标签，不依赖颜色区分已连接、过期和未应用。
- 数字带单位，等宽数字避免刷新抖动；状态变化不抢夺输入焦点。
- 主要点击区域至少 44 × 44 CSS 像素，输入文字至少 16 像素。
- 明主题下验证标签、禁用原因、输入文字、占位符和选中态可见性。
- 保存错误、连接失败及数据过期使用持续页内反馈；toast 只作辅助。
- 扫描选择和切换确认使用现有页内交互，不能依赖 iOS Captive Portal 的 `confirm()`。
- 模式选择使用语义明确的单选控件，支持键盘焦点、标签关联与必要的状态播报；每秒读数不持续触发屏幕阅读器公告。

## 10. 后续实现所需契约

本节是设计所需数据边界，不代表已新增接口或字段。

**持久配置**：功率来源、上游功率计身份及地址类型、校正模式、瓦数偏移、百分比调整。真实踏频不单独存设备身份，始终跟随绑定功率计；模拟踏频参数仅供模拟来源使用。心率复用现有参数、联动/固定选择及 `broadcast_mask` 对应开关，不新增真实心率来源。来源身份与 Pages 的 DIS 身份覆盖分离，不自动克隆真实设备名称，避免 App 中两个同名设备。

**会话状态**：启动/测试/停止、上游功率计句柄、连接阶段、真实功率及真实踏频有效性与采样时间、曲柄事件状态、重连窗口、下游连接与订阅、实际校正快照、模拟心率输出、通知统计。测试结果与运行状态不得写入 NVS。

**前端草稿**：选中来源、设备候选、未保存校正、验证错误。运行时轮询只更新遥测，不重写草稿。

配置保存复用 `/api/config` 的完整提交与版本核实；关闭 WiFi 复用 `/api/close-wifi`。新增桥接命令接口只处理启动、停止及测试会话，不承担隐式保存。扫描结果缓存可复用，但候选结构和筛选规则必须改为桥接专用，不依赖旧模板模型。

运行时按字段组合快照：功率取真实输入校正结果，踏频取同一上游的真实曲柄结果，心率取选定模拟模型结果，再按有效性和广播开关发送。不能先生成一份模拟功率快照后只替换功率数值，否则会让踏频错误地继续模拟。

配置 schema 与 BLE 配置五组读写需同步扩展；旧配置迁移默认保持模拟来源、无绑定、原值转发，避免升级后自动切入桥接。新网页必须检查固件能力，旧固件不支持时显示原因而非可点击空入口。

固定两连接资源分工：一条上游功率计、一条下游 App。活跃桥接时不得启动任何要求第三条 central 连接的固件操作；不能抢占上游或让 HTTP 请求超时。

首版只有一个上游功率计；不接独立踏频计或心率带，必须桥接该功率计附带的 CPS 曲柄数据，不桥接其心率；不实现参考设备自动拟合，不透传骑行台控制，不改变设备开机 WiFi 行为。

实施影响范围：`main/web/`、`wifi_portal`、`app_main/app_state`、新增持久桥接模块、`radio_ctrl` 生命周期协调、BLE 输入/输出 codec、`config_store/NVS`、BLE 配置协议、mock、协议与设备门禁，以及对应规则和用户文档。

## 11. 验收场景

以下为后续实施验收要求；本次只有设计文档检查。

1. 首次扫描、取消、空列表、同名及未命名 CPS 设备均有明确行为。
2. 设备连接成功却没有通知时不显示“数据正常”；有效 0 W 能完成测试。
3. 固定偏移和百分比正负参数符合公式；零输入、非法输入、舍入和范围边界可验证。
4. 草稿预览变化不影响实际输出，保存失败不丢草稿或改变旧值；请求结果不明时能核实。
5. 同一功率计的 CPS 曲柄字段能计算并桥接真实踏频；无曲柄字段、停踩、回绕和非法时间差均不会泄漏旧值或模拟值；心率能模拟或关闭。
6. 上游断开时功率立即归零且真实踏频失效，通知过期在阈值内执行同一保护，恢复新样本后继续；重连按窗口停止；模拟心率遵循固定/联动规则。
7. App 未连接与功率计失联分别显示；监测不把通知提交当 App 接收证据。
8. 更换设备、停止、切回模拟和保存关闭 WiFi 无隐式保存或错误自动切源。
9. WiFi 正常关闭和超时后已运行桥接继续；重启恢复“待启动”、功率保护零输出与踏频无效状态，模拟心率按已保存设置运行。
10. 功率、功率＋真实踏频、功率＋模拟心率、三项同时输出的组合正确；联动心率基于有效原始功率，校正不会改变其负荷；桥接不能被 App 控制后误入 ERG。
11. 手机浅/深主题、未应用状态、禁用原因、保存错误和输入焦点保持通过视觉检查。
12. 上游＋下游＋WiFi 配网并行真机验证，确认通知节拍、内存、上下游断线恢复和生命周期无冲突。
