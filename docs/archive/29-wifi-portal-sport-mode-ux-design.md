# WiFi 配置端运动模式交互收敛设计

> 归档于 2026-11-05：交互已实施，当前草稿/已应用规则与跑步术语已合入 [技术参考](../dev/01-technical-reference.md)，保留设计过程用于追溯。

日期：2026-11-05

## 目标

切换运动模式但尚未保存时，不展示属于旧 profile 的实时输出，避免用户把设备当前输出误认为新模式预览。保存成功后，实时区必须只显示已应用 profile 的数据和术语。

本轮同时收敛跑步模式中的状态文案、服务说明和可访问性，不新增配置字段、API、NVS schema、BLE 服务或运行时缓冲。

## 当前问题

运动切换按钮修改 `state.draft.sport`，实时输出读取 `state.applied`。因此设备仍在骑行模式时点击“跑步”，右侧已显示跑步配置，但左侧仍显示“模拟骑行输出”。数据本身没有错误，界面却同时表达两个 profile，容易被理解为跑步配置已经生效。

跑步实时区还有以下术语漂移：

- 状态仍显示“模拟运行”“模拟输出正在运行”。
- 诊断项仍使用“曲柄事件”。
- App 服务仍固定显示 `CPS / CSC / FTMS`。
- 跑步编辑器摘要不会随“固定配速 / 配速档”变化。

## 交互方案

### 模式状态矩阵

| 已应用模式 | 草稿模式 | 实时区 | 编辑区 | 保存按钮 |
|---|---|---|---|---|
| 骑行 | 骑行 | 展示骑行实时输出 | 骑行配置 | 保存并应用 |
| 骑行 | 跑步 | 隐藏旧骑行输出 | 跑步配置单栏居中，显示待切换提示 | 保存并切换到跑步 |
| 跑步 | 跑步 | 展示跑步实时输出 | 跑步配置 | 保存并应用 |
| 跑步 | 骑行 | 隐藏旧跑步输出 | 骑行配置单栏居中，显示待切换提示 | 保存并切换到骑行 |

“隐藏”指整个实时区不参与布局，编辑区扩为单栏。编辑区顶部显示：

> 跑步模式尚未应用。保存后设备将重建跑步广播，当前 BLE 连接可能短暂断开。

反向切换时替换为骑行文案。

### 保存状态

- 保存进行中：保持旧实时区隐藏，提示“正在切换运动模式…”。
- 保存成功：`state.applied` 更新后恢复实时区，展示新 profile 的真实运行数据。
- 保存失败或结果未知：保持实时区隐藏，保留草稿和错误提示，允许明确重试。
- 用户切回已应用模式：立即恢复当前真实实时区，不需要保存。

### 跑步语义

已应用跑步模式时：

- 标题：`跑步广播`
- 状态：`跑步广播中`
- 提示：`跑步模拟正在运行`
- 说明：`速度与步频由设备本机平滑生成。`
- 诊断项：`步频状态`
- App 服务：`RSC / HRS / FTMS`
- 上游状态改为 `会话来源 / 本机模拟`
- 跑步模式摘要随选项显示 `固定配速` 或 `配速档`

骑行模式保持现有术语。真实功率桥接行为不变。

### 可访问性与操作效率

- 运动切换按钮同步 `aria-pressed`，让读屏软件明确当前草稿选择。
- 待切换提示使用状态语义，但不抢占焦点。
- 不增加确认弹窗；固定保存栏已经提供明确提交点，额外弹窗只会增加阻力。
- 模式切换保留两个 profile 的草稿字段，不清空用户输入。
- 减少动画模式继续禁用布局切换动画。

## 实现边界

前端仅调整 `main/web/index.html`、`main/web/app.css`、`main/web/app.js`：

- 给工作区增加“模式待应用”布局状态。
- 增加轻量待切换提示。
- 让实时区诊断标签和状态文案可按 profile 更新。
- 从现有 `schema_ver` 与 `/api/mem_stats` 动态显示配置版本、当前及最低空闲堆，移除硬编码诊断值。
- 复用现有 `state.draft`、`state.applied` 和保存流程。

不修改 `wifi_portal.c`、领域层、配置编码、NVS、GATT 或任务栈。压缩内联资源增量目标不超过 3 KiB，最终仍须低于 110 KiB 门禁。

## 测试设计

按 TDD 执行，先扩展生产压缩 DOM 浏览器回归并确认失败：

1. 已应用骑行时点击跑步：骑行实时区隐藏、编辑区单栏、提示和保存按钮语义正确。
2. 保存跑步成功：实时区恢复，显示速度、步频、跑步状态、`RSC / HRS / FTMS`，页面不再出现骑行诊断术语。
3. 跑步保存失败：实时区继续隐藏，草稿保留，按钮解锁并可重试。
4. 从跑步切回骑行但未保存：旧跑步实时区隐藏；切回已应用跑步时立即恢复。
5. 320、390、1440 三种宽度无横向溢出、无页面异常。
6. 运动按钮 `aria-pressed` 与草稿选择同步。
7. schema 与堆内存来自现有接口，跑步会话来源不显示桥接状态。

## 合理范围内的后续优化

本轮可以顺带完成：

- 动态保存按钮和 profile 重建提示。
- 跑步摘要、诊断术语和服务列表纠正。
- 运动切换可访问性。

本轮不做：

- 配速输入整体重构。
- 历史曲线或浏览器长时缓存。
- 新的广播开关、传感器来源或 BLE 服务。
- 新确认弹窗和多步骤向导。

这些项目会扩大协议、状态或资源边界，应在配网态最低堆水位实测后单独评估。
